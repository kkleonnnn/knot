# ADR-0001 — 分批采纳 Loop Protocol v4（第一批 = v3.1）

- **状态**：`accepted`
- **日期**：2026-08-01
- **决策者**：资深架构师（kk）
- **提案**：[`docs/governance/loop-protocol-v4-proposal.md`](../loop-protocol-v4-proposal.md)
- **落地位置**：`CLAUDE.md` §迭代循环协议 → 新增 `#### ⭐ v3.1 采纳`

---

## 背景

kk 2026-08-01：「现有的守护者/远古守护者之类的评审规则已经不足以支持更远以后的未来了，
你参考主流是怎么设立这种评审的」。

v0.9 弧（13 片）暴露 v3 的八条问题，其中**根因**是：**评审者身份绑定时间，而非领域或风险**
（`守护者 = 上一 MINOR 的 Agent`）。它产生四个后果，本弧全部实际发生 ——
知识单调过期 · 弧内绑定固化 · 产生「弧中途不能 bump MINOR」这条怪约束 · **独立性定义错了**
（用「时间距离」代理「不知道实现过程」）。

## 决策

**分批采纳 v4，本次只采三条**（kk：「按你建议走」）：

| 采纳 | 内容 |
|---|---|
| ✅ **v3.1-A** | **独立性判据** = 「评审者不知道本片的实现过程」（输入只给 Stage 1 + 最终 diff + 闸门输出） |
| ✅ **v3.1-B** | **承重面强制枚举表**（11 条，每条对应 v0.9 弧一次真实事故） |
| ✅ **v3.1-C** | **Definition of Done**（取材纪律 + 偏离说明 + 自陈错误升格为明文） |
| ⏳ 延后 | **T0-T3 档位 + PRR 生产就绪评审** → **lift 之前采**（lift 正是第一个 T3） |
| ⏳ 延后 | 角色表 5→3（本次只改 `守护者` 一行的定义，不动其余角色） |
| ▶ 本条起用 | **ADR 机制**（本文件即 ADR-0001；历史不迁移） |

### 统摄原则（本次采纳的思想内核）

> **评审的产物应当是哨兵，不是意见。**
> 意见的有效期 = 评审者上下文的寿命（本项目 ≈ 一个会话）；哨兵的有效期 = 仓库的寿命。

**为什么这条是核心而非口号**：主流靠 **two-person rule（人多）**换独立性，
而本项目是**一个人 + 一串会过期的 Agent 上下文** ⇒ 独立性是**结构性稀缺，加人换不来**
⇒ **只能用机制替代人数**。

## 后果

### 立即生效
- **「Stage 2 缺席」不再是例外情形** —— 评审者不再是特定实体，谁满足判据谁来做。
  ⇒ **`R-LP-v3-EX-1` 不再需要逐片引用**（该条**保留为历史**，不删除、不新增引用）。
- 承重面变更的 Stage 1 **必须**带 11 条枚举表的逐条回答。
- DoD 的第 2 条（取材 + **贴失败信息**）与第 5 条（**自陈错误**）成为完成条件，不再是习惯。

### 保留不动
- 三阶段评审流程（Stage 1 → 2 → 3 → 实施 → Stage 4）**形态不变**。
- `远古守护者` 角色**暂留**（v4 提案主张废除，但那属延后批次）。
- `R-LP-v3-EX-2 / 2.1 / 3 / 3-1` 与 `override-cumulative-log.md` **全部保留**为历史治理留痕。

### 遗留未解（v4 提案 §7，需后续 ADR）
1. **档位判定需要一份「承重路径清单」，而那份清单本身会漂** ⇒ 应当**从代码派生**
   （候选：从 `.importlinter` 契约 + 既有哨兵覆盖面反推），**尚未设计**。
   ⇒ 这是「T0-T3 档位」延后的**真实原因**之一，不只是分批稳妥。
2. 枚举表会随新事故增长 ⇒ 回流纪律已写进 CLAUDE.md（v3.1-B 末），但**回流本身没有守护**
   —— 属「散文规则」，与 v3.1-B 第 5 条自指。**登记为已知弱点。**

## 备选与否决理由

| 备选 | 否决理由 |
|---|---|
| **一次性全换 v4** | 角色表 5→3 + 档位 + PRR 同时落，会让本弧剩余 6 片的评审形态在中途改变 ⇒ 与「弧内保持连续上下文」冲突（正是 v3 那条怪约束的教训） |
| **只改 `守护者` 定义、不采枚举表** | 独立性判据解决「**谁**来评审」，但不解决「**评审什么**」—— 而本弧的漏项恰恰是后者（守护者两次自认漏项） |
| **不动协议，继续逐片写例外** | 用 kk 自己的 `R-LP-v3-EX-3` 衡量已过线：**例外反复引用却不升格** = 承诺静默蒸发的形状 |
