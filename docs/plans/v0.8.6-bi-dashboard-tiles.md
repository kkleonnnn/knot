## §0 一句话目标

把仪表盘从「一张报表 = 一条名义 SQL + 一坨手写静态 `dashboard_config`」升级为「**一个板块(tile) = 一条自己的 SQL + 一个类型 + 一份冻结快照**」，支持板块 reorder + resize，admin 结构化 builder 编辑、analyst 只读消费。

## §1 范围与决议（kk 2026-07-08 拍板 4 决策 + 3 次级默认）

### 1.1 已锁 4 决策

| # | 决策 | 选定 | 理由 |
|---|------|------|------|
| D1 | tile 存储 schema | **新建 `bi_report_tiles` 子表** | `to_dto` 脱敏只 pop 顶层 `sql_text`（`bi_report_service.py:185`）→ tile SQL 塞 JSON 会泄漏给 analyst 破 R-BI-6；子表逐行复用已验证 `d.pop('sql_text')`。新表 = 幂等 `CREATE IF NOT EXISTS`，无 ALTER 舞蹈，零迁移优势对 JSON 方案几乎不成立。 |
| D2 | 刷新粒度 | **整表原子刷新** | 一个「重跑」跑完所有 tile SQL，report 级 `refresh_seq` +1；②c 调度直接复用 `refresh(report_id, sentinel)`。整块走 `run_in_executor` 卸载事件循环。 |
| D3 | KPI tile 数据 | **原始标量 SQL** | tile SQL 返标量（第一行第一数值列 / 或 `viz_config.valueCol`）+ 格式 spec；**不引 `formula.js`**（保留 wide-table 专用，不把电子表格公式承重面扩到仪表盘）。 |
| D4 | reorder/resize | **顺序 + 列跨度** | `sort_order` + `grid_span`(占 1/2/3 列)；手写 HTML5 draggable 排序 + 宽度档位；贴现有 CSS auto-fit grid。**不做**自由 x/y/w/h 网格引擎（R-186 无 DnD 库，pointer-math 引擎重且易 bug）。 |

### 1.2 tile 类型闭集（v1）

`kpi(单数值) | line(折线) | donut(圆盘) | bar(横条) | table(表)`。渲染复用现有资产（§4.2）；`insight` **不是 tile**，保留为报表级 footer（`InsightCard`）。

### 1.3 三次级默认（手册按此处理，资深可否决）

- **S1 报表级 `sql_text`**：dashboard 保留名义占位（builder 存 `SELECT 1`，过 `is_safe_sql`）；**不动** `schema.sql` 的 `sql_text TEXT NOT NULL` 约束（最省，零 ALTER 风险）。tile SQL 全在子表。
- **S2 data_source**：v1 tile **继承报表级** `data_source_id`（一个仪表盘绑一个源）；跨源 dashboard（per-tile source）**推后**。
- **S3 dashboard 导出**：**【终审裁定 C-1】v1 前端隐藏/禁用** dashboard 的 CSV/Excel 按钮（`BI.jsx` 加 `report_type!=='dashboard'` 门控）+ 后端 `_report_rows_or_404` 闸改**按 `report_type=='dashboard'` 拒**（非仅 rows-空 → 防 wide→dashboard 转换残留旧快照静默导出，见 §9 B-7）。导 table tile 快照推 v1+。

## §3 数据模型与后端设计

### 3.1 新表 `bi_report_tiles`（`schema.sql`）

```sql
CREATE TABLE IF NOT EXISTS bi_report_tiles (
  id                 INTEGER PRIMARY KEY AUTOINCREMENT,
  report_id          INTEGER NOT NULL,                  -- 软引用 bi_reports.id（无硬 FK，镜像 report_folders）
  tile_type          TEXT NOT NULL DEFAULT 'kpi',       -- kpi|line|donut|bar|table
  title              TEXT,
  sql_text           TEXT NOT NULL,                     -- per-tile 只读 SQL（存前过 is_safe_sql）
  viz_config         TEXT,                              -- JSON 列/系列/格式映射（复用 column_config 风格）
  sort_order         INTEGER NOT NULL DEFAULT 0,        -- reorder
  grid_span          INTEGER NOT NULL DEFAULT 1,        -- resize：占 1|2|3 列
  last_run_rows_json TEXT,                              -- per-tile 冻结快照 rows[:cap]
  last_run_truncated INTEGER DEFAULT 0,
  last_run_ms        INTEGER DEFAULT 0,
  last_run_at        TEXT,
  last_run_error     TEXT,                              -- per-tile 错误（一 tile 挂不连累其余）
  created_at         TEXT DEFAULT (datetime('now','localtime')),
  created_by         INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_bi_report_tiles_report ON bi_report_tiles(report_id, sort_order);
```

- **无 per-tile `refresh_seq`**（D2 整表原子 → report 级 `bi_reports.refresh_seq` 是唯一 staleness 信号）。
- **无 per-tile `data_source_id`**（S2 继承报表级）。
- **无硬 FK**：镜像 `report_folders` 软引用；删报表时 service 层级联删 tiles（§3.2）。
- `base.py`：新表由 `schema.sql` executescript 建（`base.py:29` 先跑），**无需 ALTER**；`dashboard_config` 列保留不删（降级为报表级元数据：insight + 可选）。

### 3.2 repo 层：新 `bi_report_tile_repo.py`（thin，镜像 `bi_report_repo.py`）

- `list_by_report(report_id)` → tiles（按 sort_order）· `get_tile(id)` · `create_tile(...)` · `update_tile(id, **_UNSET 哨兵)` · `delete_tile(id)` · `delete_by_report(report_id)`（级联）· `update_tile_last_run(id, rows_json, truncated, ms, at, error)`。
- 各 CRUD 自开/提交/关 conn（`get_conn()`），与现有 repo 一致。

### 3.3 service 层：`bi_report_service.py`

- **tile CRUD（经报表 PUT payload diff-by-id，不新增 endpoint）**：报表 create/update 的 payload 带 `tiles: [{id?, tile_type, title, sql_text, viz_config, sort_order, grid_span}]`。service：入参每 tile 有 `id` → update（**保留其快照**）；无 `id` → insert；库内存在但不在 payload → delete。→ **保证编辑配置不清未改 tile 的快照**。**【B-1 🔴】** diff 前须 `existing = {t['id'] for t in repo.list_by_report(report_id)}`；payload tile 带 id ∉ existing → 拒/忽略（防一个 report PUT 越权覆盖他报表 tile）—— 见 §9。
- **per-tile 安全**：每 tile `sql_text` 过 `_validate_sql`（`is_safe_sql`，fail-closed → `SqlNotReadOnly` → api 400）；**tile 数上限** `_MAX_TILES = 30`（**C-2**：placement 同 `_MAX_OVERLAY_CELLS` 在 **api 层**）超限 400。
- **refresh dashboard 分支**：`refresh(report_id, admin)` 若 `report_type=='dashboard'` → `list_by_report` → 循环每 tile：resolve 引擎（report `data_source_id`）→ `execute_query(engine, tile.sql_text)` → `update_tile_last_run(...)`（per-tile error 入 `last_run_error`）；循环后 **【B-3 🟡】** report 级 `refresh_seq` 走新 repo `touch_refresh_seq(report_id)`（bump-only，不写报表级 `last_run_rows_json`）。wide_table 分支 = 现有单 SQL 路径 **byte-equal 不动**。返回 per-tile summary（`{tile_id, rows_count, error}[]`）。
- **路由卸载**：`api/bi_reports.py` refresh 路由把整块 dashboard refresh 走 `loop.run_in_executor`（唯一先例 `admin/datasources.py:60-64`），防 N 查询阻塞事件循环。**【B-6 🟡】** 审计 detail 抽取按 `report_type` 分支（dashboard → `{tile_count, error_count}`；wide_table → 现 `{row_count, error}` 不动）。
- **脱敏 R-BI-6【B-2 🔴】**：tiles **组装放 getter**（`get_report`/`list_all`，admin+analyst 都得 tiles）；`to_dto` 仅对**非-admin** 逐 tile **深拷 dict 后 pop `sql_text`**（`{**report}` 是浅拷，in-place pop 会 mutate 共享 repo tile dict 污染同进程 admin 路径）；`viz_config`/展示层保留。guard test 断 **list + get 两路径** 非-admin 每 tile 无 `sql_text`（镜像 v0.7.27 全解包点）—— 见 §9。
- **级联删**：`delete_report` 先 `delete_by_report`（tiles）再删报表（镜像 `delete_folder` reparent 模式 `:82-92`）。

### 3.4 api 层：`api/bi_reports.py`

- `ReportCreateRequest`/`ReportUpdateRequest` 加 `tiles: list | None`（open dict，Pydantic 无 tile 子 schema，校验在 service）。
- tile 增删改排 = 报表 PUT → 复用 `bi_report.update` 审计 emit（**无新 AuditAction Literal**，审计计数 58 不变）。
- refresh 路由：dashboard 走卸载 + 返回 per-tile summary + 审计 `bi_report.refresh`（detail 按 report_type 分支，见 §9 B-6）。
- **【B-7 🟡】导出闸 by report_type**：`_report_rows_or_404` 闸改 `if report_type=='dashboard': 400`（非仅 `if not rows` → 防 wide→dashboard 转换残留旧非空快照静默导旧数据）；**且** `BI.jsx` CSV/Excel 按钮加 `report_type!=='dashboard'` 门控（草案未点名此编辑，C-1 落地）。

## §5 验收标准（观测口径，非步骤）

1. **admin 建仪表盘**：加 ≥3 个不同类型 tile，各写自己 SQL + 选类型 + 设跨度 + 拖拽排序 → 保存 → 重跑 → 每 tile 渲染其 SQL 结果（KPI 标量正确 / line/donut/bar 图正确 / table 动态列）。
2. **analyst 只读**：打开同仪表盘看得到全部渲染结果，`GET /api/bi/reports/:id` 返回的 `tiles[]` **每个都无 `sql_text`**（per-tile 脱敏）。
3. **只读校验**：任一 tile 写非只读 SQL（INSERT/UPDATE/...）→ 保存 400 `SqlNotReadOnly`。
4. **DoS 上限**：tile 数 > `_MAX_TILES` → 400。
5. **原子刷新 + 隔离**：一次重跑刷新所有 tile；某 tile SQL 失败 → 仅该 tile 显错（`last_run_error`），其余正常；report `refresh_seq` +1。
6. **布局持久**：reorder + resize → 保存 → 重载后顺序/跨度不变。
7. **快照不丢**：编辑配置（改标题 / 加删 tile）后，未改 tile 的快照保留（不被 wipe）。
8. **②c 就绪**：`refresh(report_id, sentinel)` 可 headless 调（无 Request 依赖）。
9. **wide_table 零回归**：宽表报表建/编/重跑/导出/覆盖层公式全 byte-equal 行为不变。
10. **闸门全绿**：pytest 全套件（+ 新 tile repo/service/api tests + per-tile 脱敏 guard + per-tile SQL 校验 guard + refresh 多-tile + 级联删）· eslint · vitest · **R-94（bi/ 全登记 EXPLICIT_LIMITS）** · doc-invariant（KnotLogo 渲染集仍 4 / 版本 4 源点 == `v0.8.6`）· R-BI-1 byte-equal（`git diff` ASK 侧 0 触）· eval-free。
11. **VRP**：tile 视觉复用 buildTheme token + `Card` 壳 + `CHART_COLORS` + Shared charts；`git diff` 除 §6 目标文件外 byte-equal。
