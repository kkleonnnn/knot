## §2 触发架构（K8s CronJob → 内部 tick 端点）

```
K8s CronJob（每 N 分钟，运维侧配置）
   └─POST /api/bi/scheduler/tick   Header: Authorization: Bearer <KNOT_SCHEDULER_TOKEN>
        └─ 端点（token 门）：扫 due schedules（enabled=1 AND next_run_at<=now）
             └─ per schedule：DB 原子认领（防重叠 tick 双打）→ refresh(report_id, sentinel)
                  → 记 fire 台账（ok/error/no_engine）→ emit bi_report.refresh 审计（trigger=scheduled）
```

- **多副本安全**：CronJob 单次外部触发经 K8s Service **只路由到一个 pod**；**应用内零常驻 loop** → 天然无 per-pod 重复 fire（prestudy 首选方案）。
- **DB 原子认领（belt-and-suspenders）**：`UPDATE bi_report_schedules SET last_fired_at=?, next_run_at=<recompute> WHERE id=? AND enabled=1 AND next_run_at<=?` → 看 `rowcount==1` 才 fire。防两个重叠 tick（长 tick + 下一次 CronJob）或重试双打同一 schedule。**不在 SQLite 上做跨 pod 分布式锁**（prestudy 明确 SQLite 是差的锁基底）——单触发 + 每行认领足够。
- **tz**：`next_run_at` 计算复用 `knot/core/time_resolver._TZ`（Asia/Shanghai），**不用容器 UTC 墙钟**（否则偏 8 小时 fire 错点）。日刷默认触发时刻落在上游 D-1 ETL 之后（如 07:00–09:00 CST；报表 SQL 本身是 D-1 窗口，refresh 只重跑，节奏须在数据新鲜之后）。
- **token 门**：`KNOT_SCHEDULER_TOKEN`（新 env）。端点比对 Header bearer；**未设 token → 端点 503（scheduler disabled）** = 安全默认（不误触发）。tick 端点**不接** `KNOT_SEMANTIC_LAYER` flag（BI 刷新与语义层无关）。

## §3 数据模型（schema.sql 末尾追加 2 表；base.py 幂等迁移）

仿 `semantic_monitors`(配置) + `monitor_trigger_audit`(台账) 双表范式；`CREATE TABLE IF NOT EXISTS`；`datetime('now','localtime')` 默认；soft ref 无硬 FK；**OOS-1 严禁 tenant_id**（用 catalog_id / report_id）；每表中文注释。

```sql
-- bi_report_schedules — ②c 报表定时刷新配置（per-report；OOS-1 无 tenant_id）
CREATE TABLE IF NOT EXISTS bi_report_schedules (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  report_id INTEGER NOT NULL,                 -- soft ref bi_reports.id
  catalog_id INTEGER NOT NULL DEFAULT 1,      -- OOS-1 水平切分
  enabled INTEGER NOT NULL DEFAULT 1,
  cadence TEXT NOT NULL DEFAULT 'daily',      -- 枚举 daily | hourly | every_n_hours（非 cron 表达式）
  interval_hours INTEGER,                      -- every_n_hours 时用；daily/hourly 忽略
  run_at_hhmm TEXT,                            -- daily 触发时刻 'HH:MM'（Asia/Shanghai）
  next_run_at TEXT,                            -- 下次触发（tz-aware localtime 串）
  last_fired_at TEXT,
  created_by INTEGER,                          -- schedule 拥有者（授权与审计归属）
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  UNIQUE(report_id)                            -- 本期一报一 schedule（1:N 顺延）
);
-- bi_report_schedule_fires — 触发留痕台账（append-only；可观测 + 去重依据）
CREATE TABLE IF NOT EXISTS bi_report_schedule_fires (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  schedule_id INTEGER NOT NULL,
  report_id INTEGER NOT NULL,
  status TEXT NOT NULL,                         -- ok | error | no_engine | skipped
  error TEXT,
  refresh_seq INTEGER,
  fired_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE INDEX IF NOT EXISTS idx_schedule_fires_sched ON bi_report_schedule_fires(schedule_id, fired_at);
```

> **快照侧不加列**：`bi_reports` 已有 `last_run_* / refresh_seq / last_run_by`（注释「②c 调度 sentinel」）；调度跑完复用 `update_last_run(last_run_by=<sentinel>)` / `touch_refresh_seq`。

## §6 验收标准

1. **tick 门**：无 `KNOT_SCHEDULER_TOKEN` env → tick 503；有 env、错 token → 401；对 token → 200 扫 due。
2. **端到端**：CronJob（或手 curl）打 tick → due 报表 refresh → `refresh_seq` bump + 快照更新 → fire 台账 +1 行（ok）+ 审计 `bi_report.refresh`(trigger=scheduled) 1 行。
3. **幂等/防重**：连打两次 tick（模拟重叠）→ 同一 schedule 只 fire 一次（原子 claim rowcount 守），next_run_at 已推进。
4. **错误可观测**：SQL 失败 → fire 台账 status=error + error 文案，**last-good 快照不被抹**（§7 加固）；engine None → status=no_engine，快照保留。
5. **权限**：schedule CRUD 端点 `require_report_perm("schedule")`（非 admin 无 grant → 403）；OOS-1 表无 tenant_id。
6. **tz**：daily run_at_hhmm 计算的 next_run_at 落在 Asia/Shanghai 正确墙钟（UTC pod 上验证不偏移）。
7. **前端**：`can('schedule')` 才见/可点「定时」；ScheduleModal 存/读配置；next-run/last-fire/fire 历史可见。
8. **审计守护**：`bi_report.schedule` + `bi_report.refresh` 各 ≥1 emit（`tests/api/test_metric_invariant_guards.py` 绿）。
9. **闸门**：4 源点 version 0.8.16→0.8.17 + CHANGELOG（1 Unreleased）+ doc-invariant + route count 断言 + 18 屏 byte-equal（仅 BI.jsx + 新文件）+ 无新依赖 + 全量 pytest 绿。

- **权限语义**：定时 fire/配置用 `schedule` 权限；手动 refresh 仍 `edit`（边界勿混）。
- **安全**：tick 端点 token 门（`KNOT_SCHEDULER_TOKEN`），无 token → disabled；不接语义层 flag。
- **★ 加固红线（自主运行数据安全）— 守护者 B-1，覆盖两分支**：
  - **wide_table**（`refresh` :256-262）：SQL 失败 `_exec_one` 返 `snap=[]`(:229) → 无条件 `update_last_run(rows_json=[])` 抹 last-good 且 error 不持久化。
  - **tile**（`_refresh_tiled` :281-286）：per-tile SQL 失败 `update_tile_last_run(rows_json=[], error=err)` → 同样 []-抹该 tile last-good rows（虽存了 error）。
  - → 本 PATCH 改 **skip-write-on-error 覆盖两分支**：SQL 失败时**保留上次 good rows_json**，只更新 error/last_run_at（tile 已存 error 保留，rows 不抹）；engine-None 早返（:275）已对，补的是 SQL-error 这条。error 进 fire 台账。无人值守下「一次瞬时 SQL 错抹好数据」不可接受 —— **wide_table 与 dashboard tile 是同一个坑，必须两分支都做**。
- **B-2 tz None 兜底**：`compute_next_run` guard `_TZ is None`（time_resolver.py:27 fallback）。
- **B-3 timing-safe token**：tick token 用 `secrets.compare_digest`。
- **B-4 原子 claim 同语句 recompute**：claim 的 `WHERE enabled=1 AND next_run_at<=?` + `SET last_fired_at=?, next_run_at=<recompute>` 必须**同一 UPDATE**，rowcount==1 才 fire（净新，非 monitor_repo 拷贝）。
