## §1 决议（D1–D11）

### D1 ② = **强制 `source_id`**，退役 env 模式**与**直填模式

- **删** `executor.py:90-128` 的 env 模式 · **删** `base.py:35-37` 三个 TypedDict 字段 ·
  **删** `_template_catalog.py:49-60` 的注释示例。
- `resolve_spec` 保持**无条件从 datasource 行取** `base_url` / `auth_header` / `auth_value`（今天的实际行为），
  **新增**：spec 无 `source_id`（或该 source 非 http 型）⇒ `pick_http_route` 返 `None`（**软降级 + 必须记日志**
  —— 否则就是 v0.7.29b 的静默落 SQL），**且** `execute` 侧 `base_url` 空 ⇒ `HTTPAuthError`（硬边界，不依赖上游降级）。
- **为什么直填也退役**（守护者 §IV 保留并确认「这不是搭便车，是 ③ 的前提」）：直填 `base_url` 由**零校验**
  `PUT /api/admin/catalog` 写入 ⇒ 绕过 `datasources.py:150,194` 的写侧 allowlist 门 ⇒ **③ 的正确性依赖
  「base_url 只能来自过了写侧门的数据源行」**。

### D2 ③ = `tenants.allowed_http_hosts` 列（TEXT，逗号分隔），**per-tenant 替换，永不取交集/并集**

```sql
ALTER TABLE tenants ADD COLUMN allowed_http_hosts TEXT;   -- NULL = 未配置；'' = 显式全拒绝
```

**⭐ M1（本片唯一能把 fail-closed 写成 fail-open 的地方）—— 判据必须是 `is None`，不得用真值判断：**

| 列值 | 判据 | owner | 非 owner |
|---|---|---|---|
| `None` | `col is None` ⇒ **未配置** | 回退 env + 启动 WARN（D3） | **空集 = 全拒绝** |
| `''` | 已配置（**为空**） | **空集 = 全拒绝**，**不**回退 env | 空集 = 全拒绝 |
| `' '` | 已配置（解析出空） | 同上 | 同上 |
| `' , '` | 已配置（解析出空） | 同上 | 同上 |
| 非空 host 串 | 已配置 | **该列的 host 集** | **该列的 host 集** |

若写成 `if col:` 或 `if col and col.strip():` ⇒ `''` / `' '` **落回 env** ⇒ **部署方明确表达的「禁」被静默
变成「按 env 放行」= fail-open**，正是 D2 要防的。配一条**参数化测**覆盖上表四形态 × owner/非 owner。

**为什么替换而非交集**（守护者 §IV 确认「交集是反向的」）：与 env 取交集 ⇒ 为让租户 #2 访问 host X，
部署方必须把 X 写进 env，而 env 是 **owner 的** allowlist ⇒ **给客租户开权会同时放宽 owner 的可达面**。
⇒ 每租户一份，**永不取并集**（配哨兵）。

### D3 owner 回退 env + **启动期 WARN**（单一去向的迁移路径，不制造漂移）

- owner 列为 `None` ⇒ 回退 env ⇒ **现网行为逐字不变**（内测服 ConfigMap 不动即可继续工作）。
- 启动期 WARN 一次（照 v0.9.6 `warn_if_owner_tenant_not_served` 的既成形状）。
- **不做启动期自动 seed**（把 env 值写进列）：那会制造**漂移** —— 运维改 ConfigMap 重启后列不跟随，
  形成「改了没反应」的静默 no-op。回退 + WARN 让 env 在迁移完成前**保持权威**。
- ⚠️ **WARN 只报 env 名，绝不报 env 值**（#262；v0.9.5 must-fix 同款），**且不枚举 host**。

### D4 解析点 = `url_allowlist.get_allowed_hosts()`（三个生产调用点**零改动**自动跟随）

`is_url_allowed` / `check_url_allowed` 签名不变 ⇒ `executor.py:133` + `datasources.py:31,66` 自动变 per-tenant。

**⭐ M2 —— 取列必须 `.get("allowed_http_hosts")`，不得 `ctx[...]`：**
ctx 契约（`tenant_context.py:38` docstring）**只保证 `id` / `db_dir`**；实测测侧**恰 15 处**手工构造
`set_active_tenant({...})`，**无一处带新列**（多数只有 `{"id":…, "db_dir":…}`，`test_self_built_ctx_prefix` 甚至只有 `{"id": 1}`）。
下标 ⇒ 15 处全 `KeyError`；`.get()` ⇒ `None` ⇒ 非 owner 拒 / owner 回退 env，**两个方向都安全**。

**契约变化须写明**：`get_allowed_hosts()` 从「永不抛」变成「**无 tenant ctx 时抛 `TenantContextError`**」。
- 与仓内 fail-closed 纪律一致（`get_conn` 同形）；两个生产调用点都在请求路径内；scheduler tick 走
  `resolve_single_tenant` 建 ctx。
- **刻意不 catch**：v0.9.4 MF3 的教训是「fail-soft 吞 `TenantContextError` = 安全信号静默丢失」。
  这里吞掉虽是 fail-**closed**（空集=拒绝），但会**掩盖 ctx 缺失这个事实**；让它响。
