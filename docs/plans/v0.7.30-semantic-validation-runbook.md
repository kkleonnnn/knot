# v0.7.30 语义层验证 runbook — parser 命中率自测（kk 唯一可跑）

> **取代 v0.7.17 runbook**（那版仅 10 metric / v0.7.17 覆盖；现已 41 metric + 编译七刀全覆盖）。
> **目的**：语义层「解析半扇」（parser NL→LogicForm 命中率/误判率/漏判率）是全项目**唯一未测的黑盒**——29 个 parser 测试全 mock 掉 LLM。只有 kk（唯一分析师=定义者=测试者）能用真 LLM + 真 catalog 跑出这个数字。这是决定「语义层到底行不行、能否激活」的承重数据。

## 0. 运行环境（前提）

- 跑 **v0.7.30 KNOT** + `KNOT_SEMANTIC_LAYER=true`（.env 改后**真重启进程**——`--reload` 不重读 .env）。
- 本地最快：`.venv/bin/python -m uvicorn knot.main:app --port 8000`（本地 DB 已有 41 metric + OHX catalog）。OR 部署到内测服务器（须先跨 v0.6.2 强制 2FA 分水岭升级）。
- OpenRouter key 已配（parser 走 sql_planner 桶 LLM）。

## 1. 验证机制（推荐：live 问 + AdminLogicForm 审计屏读结果）

**逐步提问 → 每条在 AdminLogicForm 审计屏留痕**（admin → LogicForm 审计，v0.7.3 建的）：
- **命中条** `engine=semantic`：看编译出的 **LogicForm + SQL** —— metric 对不对？时间窗注入对不对（ads=`sta_date BETWEEN`，dwd=`sta_time >= 'x 00:00:00' AND < 次日`）？维度/HAVING/窗口对不对？
- **回退条** near-miss：看 **reason**（parser 没出 LogicForm=命中识别弱 / metric 没覆盖=注册不全 / 编译 raise=覆盖 gap）。
- **数据正确性**：命中条 SQL 丢 Doris 实跑，核数字（尤其时间窗边界——ads 最新=昨天 D-1，dwd 含今天）。

**每条打 4 类标记**（→ 算三率）：
- ✅ **命中且对**（hit + 正确 LogicForm/SQL）
- 🔴 **命中但错**（hit 但 metric/口径/时间窗错——**最危险**：带「确定性编译」徽标却错，比 LLM 幻觉更被信任）
- 🟡 **漏判**（应命中却回退 LLM——价值损失，非危险）
- ⚪ **正确回退**（应回退的确实回退——好）

## 2. 题库（按能力分层 · 每条标「期望」）

> 每层都问几条，看该能力真实命中率。metric 名见括号（判断是否命中对了）。

### T1 · 单指标 + 时间窗（ads 日聚合，最基础）
1. 本月充值多少（deposit）
2. 昨天的净充值（net_deposit）
3. 近 7 天合约交易量（future_amt）
4. 上月平台盈亏（platform_pnl）
5. 这个月注册了多少人（reg_users）
6. 今年的提现总额（withdraw）

### T2 · 分组聚合（dwd 明细，真维度 market/side/asset/user_id）
7. 本月各交易对的合约盈亏（user_future_pnl by market）
8. 各币种的充值（user_deposit by asset）
9. 本月各方向的资金费（user_funding by side）
10. 每个用户的合约手续费（user_future_fee by user_id）

### T3 · 多指标标量（同 base 多度量）
11. 本月充值和提现（deposit + withdraw）
12. 这个月合约手续费和现货手续费（future_fee + spot_fee）

### T4 · 多 base 标量（跨表）
13. 本月充值总额 和 代理总合约手续费（deposit@ads_operation + agent_future_fee@ads_agent_stat）
14. 本月注册数 和 合约盈亏（reg_users + future_pnl）

### T5 · 多 base + 维度（跨表 + 共同维度）
15. 本月各交易对的合约盈亏和资金费（user_future_pnl + user_funding，both by market）

### T6 · HAVING（聚合后过滤）
16. 本月合约盈亏超过 1 万的交易对（user_future_pnl by market HAVING > 10000）
17. 充值超过 5000 U 的币种（user_deposit by asset HAVING）

### T7 · 窗口 / 排名
18. 合约交易量最高的 5 个交易对（user_future_amt by market, rank/limit 5）
19. 各交易对按合约盈亏排名（window rank）

### T8 · 分区 top-N
20. 每个交易对盈亏最高的 3 个用户（partition by market, top 3 by pnl）

### T9 · 派生指标（÷）
21. 本月合约费率（future_fee_rate，divide）
22. 这个月净充率（net_deposit_rate）
23. 各交易对的合约费率（⚠️ **维度派生 = OOS**——应正确回退或报错，别静默算错）

### T10 · 窗口 frame（移动平均）
24. 充值的 7 日移动平均（frame ROWS BETWEEN 6 PRECEDING）

### T11 · CTE 再聚合
25. 本月盈利的交易对有几个（COUNT groups HAVING pnl>0）
26. 合约交易量 top5 交易对的成交量合计（SUM of top-N）

### T12 · 数据新鲜度路由（v0.7.19 轴 —— 关键！查含今天 → dwd，完整过去 → ads）
27. 今天的充值（→ 应走 dwd user_deposit 含今天，不是 ads 漏今天）
28. 本周注册（→ 含今天 → dwd）
29. 上月充值（→ 完整过去 → ads deposit）
30. 迄今本月合约交易量（本月=迄今=含今天 → dwd）

### T13 · clarifier 澄清（模糊 → 应弹选项）
31. 持仓盈亏（→ 应弹「已平仓/当前持仓/时间范围」澄清，v0.7.24 场景）
32. 盈亏怎么样（→ 哪个盈亏？合约/现货/平台/持仓——应澄清）

## 3. 边界（应回退 —— 验回退优雅 + parser 不乱命中）
33. 理财余额多少（→ business_rules「暂未开放」/ 无 metric → 回退）
34. 帮我写个 SQL 查 xxx（→ 非指标问法 → 回退/拒识）
35. 各国家的注册数（→ 无 country 维度 → 回退）
36. 查 user 12345 的当前持仓（→ 跨源 HTTP 实时快照，语义层 OOS → 回退）

## 4. 陷阱（误判风险 —— 必须 NOT 静默命中错的）
37. 各交易对的持仓盈亏（v0.7.22 修过：**intent=分组 → 应走 SQL 分析**，不能被「持仓」lexicon 抢去 HTTP 当前快照）
38. 本月 BTC 的合约盈亏（**Layer C 隐患**：单交易对 + 时间窗——应走 dwd 时间窗，若漏走 HTTP 快照冒充本月=silent-wrong，重点盯）
39. 各用户的充值明细（结果含数值 user_id 列 → **v0.7.30 验**：表格显示全列，但**图表/卡片不能把 user_id 当指标画**）

## 5. 记录 → 定下一刀

- **命中率** = 命中且对 / 应命中数（T1-T12 + 陷阱，约 32 条）。目标对标 v0.4.0 intent ≥90% 门禁。
- **误判率**（🔴 命中但错）—— **这是最该压到 0 的数**（带徽标的错口径 SQL）。
- **漏判分类**（🟡）：parser 未出 LogicForm / metric 未覆盖 / 编译 raise → 分别对应 parser prompt 加强 / metric 扩注册 / 编译覆盖补。
- 回报三率 + 每类回退计数 → 定：**parser prompt 优化** vs **metric 扩注册** vs **编译覆盖补** vs **直接激活**（若命中率够高 + 误判≈0）。

> ⚠️ 若命中率过低或误判率非 0 → `KNOT_SEMANTIC_LAYER` **保持 OFF**（现状正确）。有了这个 grounded 数字，才能把「语义层能否激活」从推测变成决策。
