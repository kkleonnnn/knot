## 2. ⭐ 五条偏离草案之处（**本次终审的主要材料，请逐条裁定**）

### 2.1 middleware **永不 401**（草案 D9 字面写「tid 缺失/畸形一律 401」）
**做法**：`resolve_for_request` 返 `None` 时中间件**不设 ctx**；401 责任回 `get_current_user`。
**理由**：若由中间件出 401，它必须知道「哪些路径本来就没 token」—— SPA / 静态 Mount / docs /
OPTIONS 预检 / 登录 —— **那是一份会漂移的清单**，正是 #258 刻意避开的形状（漏一条 =
打断所有跨域前端，或把带旧 token 的用户永久锁在登录页外）。
**「不设 ctx」≠ 放行**：下游碰 DB 一律撞 fail-closed ⇒ 漏网**响亮崩掉**，不静默跨租户供数。
**已验**：实测清点 138 条 API 路由中恰 4 条无鉴权（login / totp-verify / scheduler-tick / SPA）+
6 个 Mount + OPTIONS 预检，**逐条无 5xx**（`test_noauth_get_paths_no_5xx` /
`test_options_preflight_no_5xx` / step 13 的 15 种畸形头端到端）。
**请裁定**：这个「零清单」换法是否可接受；有没有我没枚举到的「无 token 但要碰 DB」的入口。

### 2.2 登录 `company` **可选**（草案 D4'' 隐含必填）
未带 → 回退唯一 active 租户。**唯一理由**：R-T-GATE 仍硬锁第二租户 ⇒ 单租户下与按代号解析等价。
不直接必填的原因：会把**当前**内测部署所有人挡在门外（老链接无 `?c=`）。
**已登记**「lift 前必须改必填」（CLAUDE.md R-T-GATE 清单 + DEPLOY 运维门 + CHANGELOG 未结清段）。
**请裁定**：这个临时允许是否可接受；登记位置是否足够（会不会随 lift 被漏掉）。

### 2.3 R-13 从「运行期自执行」补成「静态哨兵」（草案要求哨兵从标记派生）
step 5~7 我只做了运行期自执行（ctx 清成 None ⇒ 前缀内误用 ctx 当场崩），并在 §10.1 登记为偏离；
**step 12 已补哨兵**：目标集从 `clear_active_tenant()` 调用点派生（谁自建 ctx 谁自证，新端点自动纳入），
禁列从 9 个种子做**传递闭包**（554 项，任何间接碰租户库的新 helper 自动进禁列）。
⚠️ 第一版写成白名单是错的（要枚举内建方法名、`get` 名字太泛必然误放）；派生禁列第一版也有 3 条误报

**请裁定**：这个哨兵够不够；歧义方法名排除清单会不会放过真问题。

## 3. ⭐ 新插 step 5a：整套测试对中间件**零覆盖**（本片最重要的发现，请重点核）

`tests/conftest.py::_master_key_for_tests`（autouse）给**每个测试** set tenant#1 ctx，而 TestClient 在
**同一 contextvars 上下文**跑 app ⇒ app **继承**那份「环境 ctx」。实测把 `resolve_for_request` 整体改成
`return None`（中间件永不解析租户）：

| | 中间件被整体改死 |
|---|---|
| 修前 | **1437 passed, 0 failed** |
| 修后 | **262 failed, 83 passed**（仅 integration+api 子集） |

⇒ 修前**没有任何测试**在验「中间件真的解析了租户」。
**定性**：生产环境无环境 ctx（每请求干净 asyncio task）⇒ 削弱的是**测试的证明力**，不是产品行为。
**已核**：v0.9.0~v0.9.3 的 fail-closed 测都是直接调仓库/服务函数并各自显式 set ctx ⇒ **有效，无需撤回**。
**修法**守在收敛点：`NoAmbientTenantTestClient` 只在 HTTP 调用期间清环境 ctx（`finally` 复原）⇒
测试在 client 之外直接调仓库函数不受影响；TestClient 全仓仅 2 处构造 ⇒ 一次改动覆盖
**579 个 client 调用点 / 44 个文件**，且全量 **1437 → 1437 逐字相同**（零测被打红）。
另做 bisect 验证：生产码回退到 step 4（只留该 test-infra）→ 同样 1437 passed。

**请重点核**：① 这个 conftest 改动会不会**削弱**别的既有测（我只验了「不打红」，没逐测核语义）；
② 「v0.9.0~.3 的 fail-closed 测有效、无需撤回」这个判断是否成立。
