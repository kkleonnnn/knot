## 0. 机制与判定

- **命中（HIT）** = `compile_error_reason` 空 = parser 出 LogicForm 且**确定性编译成功**（带「确定性编译」徽标）。
- **回退（MISS/near-miss）** = `compile_error_reason` 非空 = parser 出了 LogicForm 但**编译歧义/gap** → 安全回退 LLM（诊断 reason 落盘）。
- **无审计行** = parser 未识别为语义 / clarifier 层拦下 = 纯 clarifier 或 ReAct 路径（边界拒识 / 澄清首轮）。
- 4 类标记：✅ 命中且对 · 🔴 命中但错（**最危险**：徽标+错）· 🟡 漏判（回退/未识别，价值损失非危险）· ⚪ 正确回退（边界该退就退）。

## 3. 承重结论：内核扎实，误差是「点状具名可修」非系统性

**全绿承重能力**（语义层存在的理由，逐条 grounded 坐实）：
- ⭐ **Layer C silent-wrong 终极隐患关闭**：Q38 本月 BTC 盈亏 **命中**（编译器正确注入本月时间窗 → 诚实报空），**不漏走 HTTP 快照冒充本月** = 编译器保证非运气。memory「唯一缺 repro 真数据错」= 本次 repro，通过。
- ⭐ **v0.7.22 位置路由陷阱**：Q37 命中走 SQL 分组（线上死在 market/side）。
- **freshness 双向**：今天/本月迄今→dwd + 上月→ads，多次比线上准（Q30 线上漏今天）。
- **编译覆盖**：HAVING(Q16/17) · 窗口排名(Q19) · 分区top-N(Q20) · 多base标量(Q14) · **多base+维度JOIN(Q15 最难)** · CTE再聚合(Q25) · 派生(Q21/22) 全命中。
- **维度感知拒识**：无 country 维/无 metric 诚实回退，绝不 GROUP BY 幻觉列（误判率于边界=0）。

## 5.6 ⭐ 新发现（live 复测 · → v0.7.32）：order_by 字段缺校验

「合约交易量最高的 5 个交易对」→ **命中·确定性编译**，但 SQL `... GROUP BY o.market ORDER BY total_volume DESC ...` —— `total_volume` 既非 metric（`user_position_pnl`）也非维度（`market`），parser 幻觉字段 → Doris `Unknown column 'total_volume'` **执行报错**。
- **两层根因**：① Q18 数据限制（无「交易量 by market」指标 → parser 抓 user_position_pnl 当替身，选错指标）② **compiler 顶层 `order_by` 字段未校验 ∈ metrics∪dimensions∪window-as_name**（having R-SL-80 / outer R-SL-120 / window 都校验，唯 order_by 裸用 `_order_limit`）。
- **定性**：命中带徽标 + **可见执行报错**（非 silent-wrong；用户见红 banner 不见错数据）；间歇（依 parser 是否幻觉 order_by）；通用健壮性缺口（任何幻觉 order_by → 报错）。
- **修法（v0.7.32）**：order_by 字段校验（镜像 having/outer alias-based）→ 不在合法集 → raise → 安全回退；须 byte-equal 现有 order_by 测试 + 含 window as_name 合法字段集。
- **连带订正**：§4 Q18「优雅回退」评估**不完整** —— 该查询有「命中→报错」失败模式（parser 变体），非稳定优雅；order_by 校验修后转安全回退。

**v0.7.32 打包**：Q24 正确日粒度 MA（parser steer 移动平均选日粒度指标，比编译器 GROUP BY 折叠轻）+ order_by 字段校验 = 「语义编译健壮性第二轮」。
