## §1 命题 + 定性（不变）

今天租户身份是**猜**出来的：每请求经 `main.py:73` 调 `resolve_single_tenant()`，语义是「恰好 1 个 active
就返它，否则 raise」⇒ **系统从不问"你是谁家的"，而是假设"只有一家"**。本片改成**带**：登录时确定 → 写进
JWT `tid` → 之后每请求从 token 读。

**定性**：R-T-GATE **仍不放开**第二租户（v0.9.5）。本片让「身份从哪来」具备多租户能力，**不是开门**。
**已实证今日缺陷**（双租户副本）：JWT payload 只有 `{sub,ver,exp}`，用 A 的 token 一字不改请求 →
tenant#1 停用 / tenant#2 启用后 **返 200 且给出另一租户数据**。

### §3.1 F-3 硬门（滚动升级）—— ✅ **资深 2026-07-27 答：现网是「关掉再起」= `Recreate` ⇒ 前提不成立**

token reload → 重登命中旧 pod → 又拿到无 tid token → …）。**R8：单次 bump `ver` 不充分** —— 判别式是

**✅ 本项已消解**：现网部署策略 = **关掉再起（`Recreate`）** ⇒ 新旧版本**不会同时 serving** ⇒ 抖动窗口
**结构上不存在**，无需改部署、无需预先 bump。
**但仍须写进 DEPLOY 两条**（否则该前提会随部署方式变更而静默失效）：
1. **升级窗口内服务不可用**（`Recreate` 的固有代价）+ **升级后全员须重登一次**（存量 token 无 tid → 401，

   登录抖动循环** ⇒ 改策略前必须先做「旧版本禁止继续签发无 tid token」或摘流。

## §4 红线

- **R-1 OOS-1v2**：`tid` 只存在于 **JWT + platform.db + 进程内 ctx**；租户库内不得新增 tenant 列。
- **R-2 fail-closed 不倒退**：无 ctx 仍 raise；middleware 解析失败**不得**回落任何默认租户。
- **R-3 R-T-GATE 不放开**：D5 的门在位；lift = v0.9.5 一行删除。
- **R-4 单租户 byte-equal**：除「登录多一字段」外行为不变。
- **R-5' 视觉改动仅 `Login.jsx`**（R9 重定）：其余 17 屏 `git diff` 0 行；`api.js`/Chat 纯回调接线**不算**视觉改动。
- **R-6 统一登录错误 = 同响应 + 五分支各恰一次 bcrypt**（R4），CI 主门为**调用计数**（F-5）。
- **R-7 tripwire 不得 fail-soft**：`assert_tenant_context` 的 raise 严禁被 `except Exception` 吞（沿用 v0.9.3 `reraise_if_tenant_error` 范式）。
- **R-8 两条签发路径同步**（B-3）：配静态 AST 哨兵断言 `jwt.encode` payload 字面含 `tid` —— 防日后第三条签发路径漏带。
- **R-9 严格类型**（R10）：`type(tid) is int and tid > 0`；禁隐式转换参与租户解析。
- **R-11 ⭐ 承重是 ③，不得只保 ①+② 去掉 ③**（守护者必修）：① 是会漂移的路径名单（#258 刻意避开的形态）、② 是客户端可控的卫生项 ⇒ 二者**均不可作为安全边界**。每个自建 ctx 的端点**入口无条件清 ctx**。
- **R-12 ⭐ ctx-free 前缀恰为两步 + 单一组合入口**（D4''-c / 守护者 I-1/I-2/Q1）：`_decode_interim` 两段化后
  **两段均私有**、对外只留组合入口（context manager）；**AST 哨兵禁组合入口之外调用第一段**。
  契约表述为「**ctx-free 前缀恰为 [验签, 取 tid]，此后一切在已建 ctx 内**」（不得列举 N 项）。顺序 `①②③⑤④`。
- **R-13 ⭐ 自建-ctx 端点的入口不变量 + 哨兵从标记派生**（守护者 Q2）：**凡自建 ctx 的端点，入口到 set-ctx
  之间禁止任何依赖 ctx 的调用** —— 含任何 `get_conn` 型仓库调用 / `audit()` / `create_token` / catalog_state /
  engine·upload 缓存（**不是**只禁 `tenant_cache_key`/`_tenant_authed_key` 两族，那太窄）。

## §6 验收（每条须 revert-to-bad 自证）

1. **⭐ 跨租户隔离（守护者 §II-2：原「A token 打 B」在本片后定义上不可表达 → 拆三测）**
   —— tid 进 token 后「A 的 token」语义**就是**访问 A、没有 B 可打；且双 active 会先被 D5 拦掉。

   - (a) **gate 测**：双 active → 请求路径 fail-closed（D5）
   - (b) **绕过 gate 的 resolver 单测**：A/B token 各自**只**映射 A/B（不经 HTTP，直调解析器）
