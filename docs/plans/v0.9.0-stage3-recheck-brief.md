## §B — 执行者 3 处 grounded 增益（需你确认接纳）

**B-1（最重要 · 偏离你的 G1，请裁）SSE ctx 修法升级 = 镜像 catalog ctx 非 request_id**
你的 G1：tenant middleware 镜像 `set_request_id` 的 set-without-reset。执行者 grounded 复现：机制成立 + 并发安全（实测 20 并发交织 + 单 keep-alive 连接顺序请求 **0 跨请求泄漏**；根因 = uvicorn 每请求 ASGI task per-request context 隔离 + query 热路径 0 context-fork）。**但取材升级**：本仓有更贴切、更强的现役先例 = **catalog ctx 三层模式**（`catalog.py:63-71` set-without-reset + `query.py:234` generator 内重捕获 + `query.py:442`/`query_steps.py:262` `assert_catalog_context` 执行前 tripwire → 漂移落 audit + raise）。**理由：tenant 是安全边界（≠ request_id 纯日志用途），必须有 runtime tripwire 兜底**。→ tenant ctx 落地 = 镜像 catalog（set + 重捕获 + `assert_tenant_context`）。你的「ASGI send 后 reset」= 过度工程，不采（真 SSE 测 + assert 已足）。**纵深评估**：uvicorn 0.49.0 opt-in `reset_contextvars`（cpython #140947，本栈未复现泄漏）。→ **请确认接纳此升级**（比你的 G1 更强，方向一致）。

**B-2 byte-equal 真命门锁定 = http_planner 每 query reload（强化你的 G2）**
grounded 复现**推翻草案「boot 后无人再 reload」** —— `http_planner.pick_http_route`（`http_planner.py:130`）**每 query 无条件 reload**（被 `query.py:290-292` SSE generator 内每 query 调）。故 serving 期 catalog 全局内容**每 query 在 request ctx 下刷新** → byte-equal 主保障是 **SSE ctx（#2）**，init 补调（命门#1）只覆盖 boot 窗口。**#2 因此同时是正确性 + byte-equal 双 must-fix**（你的 G2/G3 已指此向，本项给出 grounded 定量）。附带：`augment_schema_with_http_tables:553` = 死代码（无调用方），非第二 reload 热点。
