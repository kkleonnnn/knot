> **状态**：Stage 1 → 待 Stage 2/3 → 落 v0.7.45

## §0 决议
presenter(LLM)拿到 `question` + `sql`(含权威 WHERE 时间窗) + `rows` + `{date_block}`(今天),但 presenter.md **没指令用 SQL 时间窗叙述** → LLM 自行从今天+问题推算日期 → 算错(Q28 散文"本周 06-30~07-04" vs 权威 SQL "06-29~07-05")。修 = 加一条 prompt 指令,让 presenter 以 SQL WHERE 时间条件为权威口径。**覆盖语义 + ReAct 两路**(都靠 SQL 窗);**HTTP 成功路径 + meta-query 特例**(sql 无 WHERE)由 bullet 末句兜底(无时间条件→不编造日期)(守护者 R2)。

## §1 文件改动(精确)
**`knot/prompts/presenter.md`** 幻觉禁令段(现 L36 "不要替用户切换日期口径")后加一条 bullet：
```
- 叙述具体日期/时间范围时，以 SQL 的 WHERE 时间条件为权威口径（编译器/agent 注入，如 `sta_time >= '2026-06-29 00:00:00' AND < '2026-07-06 00:00:00'`）；不要自行从"今天"推算日期范围（易算错周一/月初/近N天边界）。SQL 无时间条件时，不在 insight 里编造时间范围。
```

## §2 红线
- **纯 additive prompt bullet**:不动既有 meta-query 段(test_F2 断言"元数据查询特例"存在,byte-present)、不动幻觉禁令**既有条目**(守护者 R4 count-agnostic)、不动 JSON 输出契约。
- **0 代码**(presenter.py/query_steps 签名不变)· 0 schema/路由/AuditAction。
- ⚠️ **部署 gotcha(同 clarifier)**:presenter.md 改动**不自动生效** —— runtime 走 `prompt_templates` DB 覆盖(本地+线上有 presenter 行)。落地后须 **re-seed**:admin UI 覆盖 presenter prompt(有审计=首选)/ 或清 DB 行回落文件默认 / 或直更 DB 行。**本 PATCH 只改文件默认**,re-seed 是部署侧动作。
