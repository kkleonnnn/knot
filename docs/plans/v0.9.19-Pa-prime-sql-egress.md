## §1 缺陷（grounded）

`api/admin/datasources.py` 的 SSRF 守卫**函数体第一行**是 `if db_type != "http" …: return`
⇒ **SQL 数据源那条出网路径零 allowlist**。租户 admin 可填任意 `db_host` / `db_port`。

⭐ **它为什么难被发现**（已折进 CLAUDE.md 的第三种伪装）：
> 按「找名单」的扫描面**结构上找不到它** —— 它不是「另一份名单」，是「**没有名单的那条路**」。

## §2 修法

### D1 —— **两道门**（初版只有一道，是错的）

⛔ **初版的错**：只把门放进 `create_engine`。而 `POST/PUT /api/admin/datasources`
**从不调 `create_engine`** ⇒ **保存成功 + 审计记 `datasource.create` + 那个源永远红着**。

⭐ **根因：我把两个不同的能力混成了一个**（本仓规则要求「门装在能力被行使的那一行」）：

| 能力 | 门 | 层 |
|---|---|---|
| 「**登记**一个指向 host X 的数据源」 | **POST / PUT** → 400 | 端点 |
| 「**连到** host X」 | `create_engine` 本体 | 适配器（纵深） |

⇒ **两道都要**。写路径那道给**可操作的拒绝**；`create_engine` 那道保证「先存进去再让它被调用」也绕不过。

**调用点分类（Stage 2 订正我的错）**：**1 处现填**（`api/database.py:38` `/api/db/test`）
+ **5 处已存**（`engine_cache.py:198/272/309` · `datasources.py:81`（`_test_source` 读**存量行**）· `:263`）。
⚠️ 初版写「2 现填 + 4 已存」，把 `:81` 误标为「存前探测」。

### D2 —— 三态语义与前两份逐字同构 + **迁移期反向 seed**（kk ②）

三态代码形状同 v0.9.7 / v0.9.18（`is None` 判据 · `.get()` 不得下标）。
⚠️ **但回退目标不同构**：`KNOT_DB_ALLOWED_HOSTS` **不存在** ⇒ 照抄会让升级当天全断
（lens B 原话：**「三态语义逐字同构，但『回退目标的存在性』不同构」**）。

⇒ **迁移期逐租户 seed**（kk ②），来源**三个**（缺一即打死一类场景）：
| 来源 | 漏了会怎样 |
|---|---|
| `SELECT DISTINCT db_host FROM data_sources`（该租户库） | 主体 |
| `users.doris_host` | **第三个 host 写入口** ⇒ 按用户配库的场景全断 |
| `cfg.DEFAULT_DB_HOST`（env `DB_HOST`） | 它是 **seed admin 的默认 host** ⇒ 默认部署自断 |

⚠️ **必须逐租户**（每家名单只含自己的 host）—— 否则退化成那份危险的全局名单。
⚠️ **与 v0.9.7「不做启动期自动 seed」的张力**：那条反对的是**从 env seed**（env 仍权威 ⇒ 会漂）；
本处从**存量数据行** seed 是**一次性 grandfather**，seed 完**没有可漂的对象**（列是唯一来源）。
⚠️ **诚实成本**：seed 会把「现在库里有什么」固化成名单，**包括历史上填过的奇怪 host**
⇒ 故 kk ③ 要求可核（见下）。

### D3 —— ④ 脱敏规则：判据从「字段名」换成「**读者是谁**」

⛔ **不能直接删掉 `_REDACTED_IN_AUDIT`** —— 那会把**理由**一起删掉。

| | 旧（v0.9.18 立） | 新（kk ④） |
|---|---|---|
| 判据 | **字段名**在集合里 ⇒ 记 `"changed"` | **这条记录的读者是谁** |
| `platform_audit` | 脱敏 | ✅ **记内容** —— 读者 = 部署方自己（平台密钥 out-of-band，v0.9.5 E1），内网主机名对他不是秘密 |
| 租户库审计 / API 响应 / 异常 / SSE | — | ⛔ **仍然绝不出现**（#262 那一族不变） |

⭐ **④ 顺带补一个真实的审计缺口**：旧规则让 `update_tenant` 改 allowlist 时**只记「changed」**
⇒ **「谁把哪个 host 加进了出网名单」查不出来** —— 对一份**安全控制**而言，
「改动防线的行为没有内容级证据」本身是洞。

⚠️ **kk 已知悉并接受的面**：平台审计表**会被备份、可能被导出** ⇒ 内网主机名随之扩散。
⚠️ **新哨兵比旧的难写**（要判定「租户可达」）—— 这是 ④ 的真实成本，**登记为本片工作量**。

### D4 —— **反向断言**（Stage 2 E13：「白送」是有条件的）

四个测文件**全部从** `tenant_repo._MUTABLE_TENANT_FIELDS` 派生（✅ 派生是真的），
但**全仓没有任何断言反向要求**「schema / migration 里的 `allowed_*` 列 ⊆ 该元组」。
⇒ 把 `allowed_db_hosts` 加进 schema + migration + resolver 却**漏加那个手写元组**，
则三份「自动」覆盖**全部静默落空**。

⇒ **本片必须补**：从 `platform_schema.sql` + 平台迁移**派生**出 `allowed_*` 列全集，
断言它 ⊆ `_MUTABLE_TENANT_FIELDS`。
⚠️ **这与本片要修的缺陷同形** —— 我扫的是「元组里有什么」，没扫「**应该在元组里而没在的**」。

## §4 验收 —— **五问② + 在哪一层成立**

> 格式：**判据** → **层** → **注入** → **前 / 后**。
> ⚠️ 凡写「抛」的，必须**在该层真的可观察**（初版栽在这里：6 个调用点全吞异常）。

| # | 判据 | 层 | 注入 | 前 → 后 |
|---|---|---|---|---|
| 1 | 非起源租户 host **不在**名单 ⇒ `POST /api/admin/datasources` 返 **400 且不落库** | **端点** | 删写路径那道门 | 前：400 + 库里 0 行 → 后：**200 + 库里 1 行** ⇒ 用**行数**当 oracle（不是异常） |
| 2 | 同上，`PUT` 改 host 到名单外 ⇒ **400 且行未变** | **端点** | 同上 | 前：行内 host 未变 → 后：**变了** |
| 3 | host **在**名单 ⇒ 正常保存（正对照，防「拦住所有人」） | **端点** | 门改成恒拒 | 前：201/200 → 后：400 ⇒ 守「没把功能拦死」 |
| 4 | `/api/db/test` 的 host 不在名单 ⇒ **不建连**，且**返回体含可操作说明** | **端点** | 删 `create_engine` 那道门 | 前：不建连 → 后：**建连**。⚠️ 该端点返 **200**（`{"connected":false,"message":…}`）⇒ **判据读 body，不读状态码、不用 `pytest.raises`** |
| 5 | ⭐ **跨租户**：租户 B 指向**租户 A 的 host** ⇒ 拒 | **端点** | 把 resolver 改成读一份全局名单 | 前：拒 → 后：**放行** ⇒ 抓住「全局名单」这个错误设计本身 |
| 6 | `create_engine` 那道门在**已存**路径也生效（`users.doris_host` 走它） | **适配器** | 删该门 | 前：拒 → 后：放行。⚠️ **在适配器层直接调**，因为端点层被 `except` 吞（§3-7） |
| 7 | ⭐ **seed 后现网不断**：迁移前有 N 个数据源 ⇒ 迁移后**全部仍可连** | **迁移 + 适配器** | 让 seed 只取 `data_sources`（漏 `users.doris_host` / `DEFAULT_DB_HOST`） | 前：N 个全通 → 后：**漏的那类断** |
| 8 | seed **逐租户**（A 的 host 不进 B 的名单） | **迁移** | seed 改成全库 `DISTINCT` | 前：B 的名单不含 A 的 host → 后：**含** |
| 9 | seed 详情进 `platform_audit`，**日志只有计数** | **迁移** | 把 host 列表塞进日志 | 前：日志无 host 字面 → 后：**有** ⇒ 内容级断言 |
| 10 | **④**：`update_tenant` 改 allowlist ⇒ `platform_audit` **记得到内容** | **仓储** | 把该列加回脱敏集合 | 前：detail 含 host → 后：`"changed"` |
| 11 | **④**：allowlist 内容**不出现在租户可达面**（API 响应 / 异常 / SSE） | **端点** | 把 `sorted(allowed)` 插回拒绝消息 | 前：响应无 host 字面 → 后：**有** |
| 12 | **D4 反向断言**：schema 有 `allowed_*` 而元组没有 ⇒ 红 | **元** | 往 schema 加一列不加进元组 | 前：绿 → 后：红 |
| 13 | 三态 × 起源/非起源逐格（**P-a 的共享性质表自动覆盖**） | 适配器 | 判据改 `if raw:` | 自动 |
| 14 | 启动 WARN 存在且接线（**P-a 的派生断言自动覆盖**） | 元 | 删函数 / 删接线 | 自动 |
