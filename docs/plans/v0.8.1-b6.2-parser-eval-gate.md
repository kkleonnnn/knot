### 0.4 三率精确定义（runbook §5 · results §0，grounded）

| 率 | 定义 | 判据 |
|---|---|---|
| **命中率** | 命中且对 / 应命中数（T1-T12+陷阱 ≈32） | `compile_error_reason` 空（parser 出 LogicForm + 确定性编译成功）**且** metric/口径/时间窗**对** |
| **误判率 🔴** | 命中但错 / total（**须压到 0**） | 编译成功带徽标**但** metric/caliber/时间窗错 —— 最危险（徽标使用户更信任） |
| **漏判率 🟡** | 应命中却回退 LLM / total（价值损失非危险） | parse None（无审计行）或 CompileError（near-miss 行带 reason）→ 回退 |
| ⚪ 正确回退 | 应回退且回退（boundary/OOS 诚实处理） | 非错误类 |

**自动 vs 人判（grounding 核心结论）**：
- **自动可测**：命中/漏判分类（`compile_error_reason` 空？）· 编译覆盖（`_build_sql` 确定性 raise-vs-SQL，0 LLM/DB）。
- **命中率**：需 **live LLM**（parse_to_logicform 是 LLM 判断，mock 即失真）。
- **误判**：`semantic_query_audit` **不记录**正确性（`AgentResult.success` 只是 DB-error flag）→ 传统上**纯人判**。**但**——**expected-LogicForm canonical 匹配可把大部分 LF-level 误判转成自动 exact-match**（产出 LF ≠ 期望 canonical = 误判，无需 live DB；outer-count 套娃 / frame-on-datetime 类**结构性**误判可这样抓 —— ⚠️ 守护者 §C-3：Q5/Q24 这两历史误判实机已被 v0.7.31/.32 compiler guard 修成**安全回退**，此处仅作 harness 演示、非当前误判实例）；**数值真相类误判残余**（守护者 §C-2 订正例：**Q3 freshness dwd-vs-ads 源路由分歧** —— LF 对但走错源产不同数字）仍需 live-DB + 人判。**⚠️ Q38（本月 BTC 盈亏）v0.7.44 重跑 = 命中 PASS**（编译器注入本月窗→诚实空不漏 HTTP，results L66/74），**非误判实例**；Layer-C silent-wrong 是**类风险**（memory「缺 repro」）非该题结果。

## §1 决议（Stage 1 提案）

### 1.1 核心设计：**expected-LogicForm 金标 + 两层评测**（对标 v0.4.0 intent，扩到 LogicForm）

corpus 每 case 标注**期望 LogicForm canonical**（hit case）或**期望回退**（fallback case）→ 用 `LogicForm.to_canonical_json()`
byte-equal 匹配自动判命中/误判/漏判。分两层：

> **⭐ 守护者 §D-4 承重澄清（canonical 保序不归一）**：`to_canonical_json` 对 **metrics/dimensions/filters 顺序保序、不归一**
> （logicform.py:45-47 `list()`；仅 order_by 归一 dict-key + 空键省略）→ canonical byte-equal 检的是 **「确定性/是否复现期望 canonical LF」，不是「语义等价」**。
> 这对激活门**恰恰正确**（parser 非确定性/漂移就该被判 differ）；但**别把它当语义等价去重**。
> **§D-5 filters 假阴最高危**：filters 是自由文本 list 保序不归一 → 等价写法（`x>10` vs `x>=11` / `a AND b` vs `b AND a`）canonical **必不等** → 合法被判 🔴 误判（假阴）。**带 filters 的 hit case 假阴风险最高**（§1.5-2 逃生舱对 filter-heavy case 提前备好）。

- **Layer 1（key-free，主 CI 强制，确定性）**——放 **`tests/services/semantic/`**（**不**放 tests/eval，避 `--ignore` 逃逸）：
  1. **corpus 良构**：每 case 有 id/question/expect；expect.mode ∈ {hit, fallback}；hit case 有 `logicform`（可 `from_dict`）。
  2. **期望 LF 编译覆盖**：每 hit case 的期望 LogicForm 经 `compile_logicform`（fixture catalog + `today_override` 定钟）
     **确定性编译成功**（0 LLM/DB）→ 断言编译器覆盖所有期望 LF（漏判「编译 raise」根因的 CI 守护）。
  3. **corpus 完整性**：应命中 case 数 ≥ N（对标 intent ≥80；语义 corpus 按 runbook 32 题定，.example 假域 ≥ 覆盖七刀+回退各类）。
- **Layer 2（live LLM，opt-in，accuracy 门禁）**——放 **`tests/eval/`**（`@_REQUIRES_KEY` + eval-live.yml）：
  对每 case `await parse_to_logicform(question, metrics, model_key, openrouter_api_key)` → 取 `res["logicform"]` →
  - hit case：产出 LF.to_canonical_json() == 期望 canonical → **命中且对**；产出非空但 ≠ 期望 → **🔴 误判**；产出 None/编译 raise → **🟡 漏判**。
  - fallback case：产出 None 或编译 raise → ⚪ 正确回退；产出可编译 LF → 🔴 误判（不该命中却命中）。
  - 聚合三率 → **hard assert `命中率 ≥ 0.9` AND `误判数 == 0`**（对标 intent 的 `assert accuracy >= 0.9`；误判更严=0）。

### 1.2 gate 语义 = opt-in eval job 断言，**非** PR 阻塞 + kk 激活裁决点

- Layer 2 的 ≥90%/误判=0 hard assert 在 **eval-live opt-in job** 跑（同 intent：label/cron/manual + secret）——**不进主阻塞 CI**（token 成本 + LLM 非确定性不该 gate 每 PR）。
- **激活裁决仍是 kk 手动 checkpoint**（memory: 「kk 跑完 runbook 拿三率…才激活」）：B6.2 把三率变**可复演**，kk 跑 eval-live（或本地带 key）拿到绿 → 连同 B6.4/6.5/6.6 清完 → 决定开 flag。B6.2 **不自动开 flag**。
- **⭐ 守护者 §E 澄清（假域 harness 自检 vs 真域激活裁决）**：Layer 2 在 **.example 假域** corpus 上的 `命中率≥0.9` assert **本质是 harness-正确性自检**（假域设计成可解析 → 应 ~100%），**非真准确率测量**；**真准确率门 = kk 在 gitignored OHX corpus 上跑 eval-live 的激活 checkpoint**。故假域 corpus 设计成**稳过**（95%+ buffer，§1.5-1）→ flaky 假红风险天然低。README 明写这层区分。

### 1.3 corpus 隐私（对标既有 .example 约定）

- **新增语义 eval corpus**（≠ 既有 intent `cases.example.yaml`）：committed `tests/eval/semantic_cases.example.yaml`（**假域** e-commerce，
  期望 LF 用假 metric 如 gmv/dau，可由执行者构造）+ gitignored 真实 `semantic_cases.yaml`（**OHX 真 metric/表/期望 LF/数值**，kk 作为定义者填）。

- **⚠️ 真 corpus（OHX metric 名/caliber/期望数字）严禁进 .example / git**（R-PA-6 脱敏链；镜像 cases.example.yaml 约定）。

### 1.4 corpus 标注来源

- **hit case 期望 LF**：由 kk（唯一定义者）提供 —— 复用 v0.7.44 重跑已知-good 的 LogicForm（那批 9 命中已人判对）+ runbook 32 题逐条期望 metric/dim/time。执行者 Stage 1 交**harness + .example 假域骨架 + schema 说明**；kk 填真 OHX corpus。

### 1.5 三 fork（Stage 3 守护者 LOCKED）

1. **LLM 非确定性 → ✅ A 单跑 hard-assert + 3 护栏（守护者 §E-1）**：flaky REAL，证据 = **results §5.6 L121「间歇（依 parser 是否幻觉 order_by）」+ memory knot-v070-stage1-state L21（Q18 07-03/07-04 逐字节同坏 LF）+ L50（Q5/Q24）**（⚠️ 守护者 §C-1：旧引「§5.5」错——§5.5 是 v0.7.31 修复后确定性复测表，无波动）。但 flaky **主要翻 hit↔fallback（抖命中率数字）非 hit↔误判**（parser 非确定性被 compiler guard 安全兜住→不产生 silent-wrong；幻觉字段多落 near-miss 回退侧）→ **误判=0 硬线相对稳**。护栏：(a) 引用订正 §5.6/memory；(b) **命中率阈值留 buffer** —— .example 假域 corpus 设计成稳在 95%+ 再 assert ≥90%，避 90% 边界抖动假红；(c) **误判=0 硬 assert 保留**（安全线）；(d) 数据点稀 → 先跑几轮 opt-in 收波动分布，不预断「频繁假红」。
