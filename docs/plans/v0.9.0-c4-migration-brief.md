## 2. 对抗评审 → 5 confirmed → 修复对照

| # | 严重度 | 发现 | 修复 |
|---|---|---|---|
| 1 | high（部署相关） | 无跨进程串行 → 并发启动可服务**空** tenant#1（`_backup_db` connect 会把被删锚点重建为空库；empty-vs-empty 假过校验）。**synthesis 校准**：`if not bak.exists()` 保住 `.bak` → 真数据存活可恢复，非「全丢」 | **flock**（数据根 `.c4-migration.lock`）串行同节点；`_backup_db` src 不存在即 raise（不重建空库）；`_verify` 拒空表库；DEPLOY 补多副本「先单副本/init-container 迁移」 |
| 2 | medium（须先违反铁律） | `_target_has_real_data` 仅判 `users>1/conversations>0` → 配了数据源但只有 seed admin 的租户库被误判残片而覆盖 | **广判据** `_USER_CONTENT_TABLES`（conversations/data_sources/knowledge_docs/saved_reports/bi_reports/metrics/messages/user_sources）+ users>1；排除 seed 非空表（semantic_layer/prompt_templates/few_shots） |
| 3 | medium | `_decrypt_smoke` 取首个非空值 → legacy 明文/空占位让**错 master key false-pass**（fernet 对非 enc_v1 passthrough 不动 key） | **只探 `is_encrypted`（enc_v1:）真密文**，遍历所有加密列所有行 |
| 4 | low（测试/dev） | gate `setdefault`+`!="1"` → 外部预设非"1"值使 pytest 迁移真实 dev 库 | conftest **无条件直写** `="1"`（同 JWT_SECRET pin） |
| 5 | low（回滚源） | 备份重生按存在性非有效性 → crash 中途留半成品 `.bak` 永不重生 | `_backup_db_atomic`（temp + `os.replace`）—— `.bak`/uploads 均原子 |

**5 rejected（synthesis 判定 stale/无害）**：crash-after-copy 触发假 raise（已被 marker 化解）· 无 fsync（已用 `.backup()` + fsync）· copy2 漏 WAL（已弃 copy2）· verify 对 byte-copy 恒真（无独立危害，加空库拒收后闭合）· 「并发全丢」被 §1 校准为可恢复。

**未采纳的 synthesis 可选建议**：resume 前把 target renamed 到 `.pre-resume.bak`。理由：resume 只在「有标记（本迁移写的，源=锚点仍在）」或「无真数据残片」下 unlink → target ⊆ 锚点恒成立，unlink 不丢唯一数据；额外 `.pre-resume.bak` 徒增文件堆积。**请守护者裁定是否仍需**。
