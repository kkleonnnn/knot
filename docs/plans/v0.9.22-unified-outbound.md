### 0.2 三处 3xx 判断**逐字重复**（实测）

`telegram.py:62` · `webhook.py:190` · `lark.py:48` 都是 `if 300 <= resp.status_code < 400:`。
⚠️ 它们**必须存在**（v0.9.21 M2：`raise_for_status()` 对 3xx **不抛**
⇒ webhook 会把「没投递」写进「已发送」审计）—— 但**没有理由写三遍**。

### 0.3 ⚠️ 新出现的设计皱褶：`url_canon` 也 import `requests`

v0.9.21 新增的 `adapters/http/url_canon` 用 `requests.Request(...).prepare()` **算 host，从不发送**。
⇒ 「**恰好一个文件可持有 HTTP 客户端**」这个哨兵口径**按文件算会误伤它**。
⇒ 判据必须能区分「**用 requests 解析**」与「**用 requests 发送**」：
**只有 `outbound.py` 可以调用 `requests.<verb>()`**；`requests.Request(...).prepare()` 不算发送。
⚠️ 这与 v0.9.21 已立的先例**同源**（「解析器不是客户端」）——
只是判据从 **import 级**下沉到**调用级**（import 级挡不住这个区分）。

## §1 修法

### 1.1 helper：`adapters/http/outbound.py`

| helper **管** | helper **不管** |
|---|---|
| `allow_redirects=False`（**不接受该参数** —— 传了即 `TypeError`） | **哪份 allowlist**（三份、方向相反、三态不同 —— v0.9.18 严禁混用） |
| **3xx ⇒ 抛**（收拢那三份重复） | 凭据怎么放 |
| 超时（**必填、无默认**） | 重试 |
| 返回 `Response` | —— |

⚠️ **禁令必须结构性，不能是默认值**：写成 `allow_redirects=False` 的默认参数，
调用方一行 `True` 就能关掉而**没有任何东西会红**。
⚠️ ⭐ **必须走 `requests.post/get/head` 的模块属性查找**（kk 已裁定）——
⛔ **不得**用 `Session()` 或 `requests.request(...)`：`tests/conftest.py` 的 `no_network` 探针
**只 patch 那三个模块属性**，且其中 3 条断言是**反向的**（`assert no_network == []`）
⇒ 换形态会让它们**静默恒真**，连带约 20 处 `monkeypatch.setattr(requests,'post',…)` 一起瞎掉。
⇒ **代价**：设不了 `trust_env=False`（代理 / `.netrc` 面关不掉）
⇒ 改为**启动期响亮说出来**（检测到 `*_PROXY` / `~/.netrc` 时 WARN：
「门校验的 host 与实际连接目标可能不同」）。**理由**：探针失效是**静默**的，代理面**可以被喊出来**。

### 1.2 ⚠️ 签名必须容纳既有用法（Stage 2 已实测，不是猜）

- `lark` / `telegram` 传 **`data=` + `files=`**（multipart，图片投递）；
- `executor` 传 **`params=`**（GET）与 **`json=`**（POST）；
- 三处依赖 `resp.raise_for_status()` / `resp.json()` ⇒ **必须返回 `Response`**。

⇒ helper 签名 = `send(method, url, *, timeout, **kw) -> Response`，`kw` 原样透传。
⚠️ **但 `allow_redirects` 必须在 `kw` 里被显式拒绝**（不是「忽略」—— 忽略等于悄悄放行一个误解）。

### 1.3 `or_catalog`：`urlopen` → helper（形态统一）

**理由不是「统一好看」**：一个能力有两种形态，正是让它成为**唯一漏掉禁令的那处**的原因。

⚠️ **换形态会改三件事，都要处置**（Stage 2 实测）：
1. **异常类型**：`issubclass(requests.RequestException, URLError)` = **False**
   ⇒ `or_catalog.py:39` 的 `except (URLError, JSONDecodeError, TimeoutError)` **全落空**
   ⇒ 网络失败会从 503 变 **500**；
2. ⭐ **500 从 fail-closed 变 fail-open**：`urlopen` 对 500 **抛** `HTTPError`（⇒ 现在 503、不写表），
   而 `requests` 对 500 **不抛** ⇒ 错误 JSON 会被当模型目录 **upsert 进表**
   ⇒ **必须补状态码分流**；
3. **UA**：`or_catalog.py:35` 显式设 `knot/0.6.0.6` —— ⚠️ 那个版本字面**已漂 30+ PATCH**，顺手修。

### 1.4 哨兵（**行为级 + 调用级**）

1. ⭐ **只有 `outbound.py` 可以调 `requests.<verb>()` / `urlopen`** ——
   口径按 **AST 调用级**（不是 import 级，见 §0.3），扫描面 `knot/`，**含别名解析**
   （`import requests as _rq` 必须被认出 —— P-a'' Stage 1 的探针就漏过它）。
   ⚠️ 禁集合要含 `httpx` / `urllib3` / `http.client` / `aiohttp`
   ⇒ 否则下一个 `import httpx` 的出网点**静默逃逸**。
2. ⭐ **helper 不接受 `allow_redirects`** —— **运行时判据**（`pytest.raises(TypeError)`），
   **不能是 AST 读签名**：`**kw` 转发下签名级判据**恒绿**。
3. **`tests/` 排除**，理由写进 docstring：差分测需要一个**独立于生产实现**的发送方式当 oracle。

## §4 v3.1-B 枚举（命中：出网 · 凭据）

1. **fail-open 面**：禁令写成可覆盖默认值 = fail-open（§1.1 结构性封死）。
   ⭐ **1 → N 自查**：helper 让出网从「各写各的」变成「都走一处」
   ⇒ **凡依赖「自己那处特殊写法」的地方都要重扫** —— 已知：`datasources.py:72` 原有的 flag ·
   `or_catalog` 的 `URLError` 捕获 · 三处 3xx 判断 · **`url_canon` 的 `prepare()`（不是发送，别收编）**。
2. **oracle + 注入**：#3/#4 起**真服务** ⇒ 注入真能产生「第二跳发生」/「错误 JSON 进表」。
3. **「那一行」/ 入口**：禁令在 helper **唯一**一行；入口由 #1 哨兵封死（**调用级**，含别名）。
5. **散文规则无守护？** —— v0.9.21 在三处写了「3xx 必须显式判」的注释，**收拢进 helper 后由 #3 守**。
6. **声明 vs 生产者**：helper 有 7 个消费者（全部出网点）。
7. **顶班**：⚠️ 若某点本来就打不通，「禁令生效」与「本来就失败」不可区分 ⇒ #8 正对照必须存在。
8. **既有测的绿是真的吗** → §2 逐条。
9. **契约冲突**：`adapters/http/outbound.py`；`api → adapters` 向下（`or_catalog` 是 api 层）—— 已有先例。
10. **策略题的影子**：`trust_env` 那条出现了「关不掉就只能喊」⇒ 已选「喊出来」，理由是**失效方式可见**。
11. **诚实收窄**：本片**不声称** —— 端口受控 · DNS rebinding / TOCTOU · headers 不受检
    （`auth_header` 可写 `Host`）· **LLM SDK 出网**（`openai`/`anthropic` 底层 httpx，
    实测 `follow_redirects=True`；⚠️ **本片的哨兵刻意不覆盖它们** ——
    那是独立一片，此处**显式豁免并写明**，不默默漏掉）· 第二家公司可以进来（代偿门仍在）。
