### 1.1 ⭐ `or_catalog`：三行 opener（**这就是全部**）

```python
class _NoRedirect(urllib.request.HTTPRedirectHandler):
    def redirect_request(self, *a):   # 返 None ⇒ 不跟随
        return None

_OPENER = urllib.request.build_opener(_NoRedirect())
```
调用改 `_OPENER.open(req, timeout=30)`。

⭐ **机理（✅ 执行者复跑确认）**：`redirect_request` 返 `None` ⇒ `http_error_302` 直接 return
⇒ 落到 `http_error_default` ⇒ **抛 `HTTPError(code=302)`**、第二跳零发生
⇒ **3xx 与 4xx/5xx 共用既有那条 `except (URLError, JSONDecodeError, TimeoutError)`** ⇒ 照旧 **503**。

⇒ ⭐⭐ **原 §1.3 那三处「换形态的连带处置」全部归零** —— 异常层级不变 · 500 仍 fail-closed · UA 不变。

### 1.2 ⛔ 为什么**不**选 (b) 换 `requests`（三条实测，全部是我原方案的错）

| # | 实测 |
|---|---|
| 1 | **fail-open 是四处不是一处**：4xx / 5xx / **以及 302 的响应体** —— ✅ 复跑 `302 + {"data":[{"id":"evil/model"}]}` 在 `requests` 下**不抛**，而 `or_catalog` 紧接着 `json.loads` ⇒ **该体被当模型目录 upsert** |
| 2 | **带一个不可关闭的凭据出境面**：`requests` 把 `.netrc` 凭据变成 `Authorization: Basic` 发出（`urlopen` 不会），且 `default` 条目匹配**任意 host**；而 `Session()` 被 kk 裁定②禁用 ⇒ `trust_env` **关不掉** |
| 3 | **异常层级重写**：`RequestException` **非** `URLError` 子类 ⇒ 三个 `except` 全落空、超时/DNS 失败从 503 变 **500** |

⇒ (b) 的唯一实质收益（单一形态让哨兵简单）值约 5 行哨兵代码，**不成比例**。

⚠️ **顺带订正我方案里一处定性反了**（lens A）：我把「设不了 `trust_env=False`」记成**换形态的代价**
—— 实测 `urlopen` **同样**走 `HTTP_PROXY` ⇒ **代理面今天就存在**，不是 (b) 引入的。
⇒ item ③ 的 WARN 仍该做，但**理由要改对**。

### ⚠️ §3-1 #2 的 oracle 必须换（lens A 的 P0-2，✅ 我认同）

原写「后：200 + 错误 JSON 被 upsert」。**但 OpenRouter 式错误体 `{"error":{…}}` 经
`payload.get("data") or []` 得空 ⇒ 0 行 upsert ⇒「行数不变」前后皆真 = 判据恒绿。**
⇒ 可区分的 oracle 是 **HTTP 状态码（503 vs 200）**，或注入**带 `data` 数组的错误体**。
⇒ **本片取「状态码 + `upserted_count`」双断言。**

### ⚠️ §3-2 lens A 还指出一处我完全没想到的下游

`Admin.jsx:166-174` 只在 catch 里报失败，200 走 `已同步 ${r.upserted_count} 条`
⇒ 若上游失败被吞成 200，前端会显示**绿色 toast「已同步 0 条」**，而 `upsert` 从不删行
⇒ **admin 无法区分「同步成功无变化」与「上游挂了」**。
⇒ (a) 下 3xx/5xx 仍抛 ⇒ 该问题**不存在**；本条作为「为什么必须保住 fail-closed」的理由记录在案。
