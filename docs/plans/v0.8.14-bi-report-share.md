## §0 一句话范围

BI 报表模式下，用户可把**仪表盘（整盘）或报表（≤50 行）快照成 PNG**，发到 admin 预配白名单里的 **Lark(飞书) / Telegram 群**。`can_share` 权限门控 + admin 策展投递目标白名单 + 加密存 IM 凭据 + 独立 egress allowlist + 分享审计。

**不做**：定时分享（属 ②c 调度器）· 公开链接分享 · 用户自由填 chat_id · JPG（用 PNG）。

## §2 关键 grounding 结论（决定设计的事实）

1. **权限层零改动**：`require_report_perm("share")` 开箱即用 —— `ACTIONS` 含 `share`（[bi_permission_service.py:14](../../knot/services/bi_permission_service.py)）· `bi_permissions.can_share` 列已存在 · `PermissionSetRequest.can_share` + `PUT /api/bi/permissions` 已能授权 · 前端 `can('share')` + `SHARE_ICON` + 占位按钮（[BI.jsx:159](../../frontend/src/screens/BI.jsx)）已在。**只差路由本体 + 转发能力 + 前端截图**。

2. **前端已握全部快照数据**：`GET /api/bi/reports/{id}` 的 DTO 已附 `tiles[].last_run_rows_json`+`viz_config`（dashboard/tabbed）/ 报表级 `last_run_rows_json`+`column_config`+`overlay_config`（wide_table）—— 就是实时组件的同一渲染源。**离屏 Snapshot 节点直接读 `selected`，后端 share 端点只接收 PNG、不下发数据**。

3. **⭐ 截图 = 手写 `foreignObject`→canvas→PNG（零 npm 依赖）**：BI 渲染面**纯 SVG + HTML、零 canvas**（仪表盘 6 类 tile 全手绘 SVG/HTML；ECharts 仅 ASK 侧且走 `renderer:'svg'`）；**样式全内联**（设计系统是内联 `style={}`，index.css 仅 3 行 reset）。→ `foreignObject` 序列化天然抓全（HTML 布局 + 内联样式随节点走）、**原生支持 oklch/color-mix**、无外部图片=canvas 不 taint。**html2canvas 是错选**（自实现 CSS 解析、不支持 oklch → 每个颜色都糊）。→ **R-186 无需引依赖、无需 chore eval**。
   - 风险（POC 去除）：字体不嵌入 → PNG 用截图端已装字体（数字仍清晰，可接受）；foreignObject 需 well-formed XHTML（React DOM 经 XMLSerializer 基本 OK，POC 验）。

4. **通知适配层不能复用**：现有只有 text-only `WebhookNotificationAdapter`（发 `{title,body,level}` JSON，无二进制槽，且 Protocol byte-equal 被测试守）→ 新建 `telegram.py` + `lark.py` 图片适配器，**不改** `Notification`/`NotificationAdapter` 契约。

5. **Lark ≠ TG（不对称）**：TG = 单次 `POST api.telegram.org/bot<token>/sendPhoto`（multipart，token 在 URL）。Lark = 三步（换 `tenant_access_token`（app_id/secret，~2h 缓存）→ `im/v1/images` 上传拿 `image_key` → `im/v1/messages?receive_id_type=chat_id` 发，**content 是双重编码 JSON 字符串**）。Lark 自定义机器人 webhook **发不了图**（只能引用已有 image_key）→ 必须走 app + im/v1。region 分 `open.feishu.cn`(飞书) / `open.larksuite.com`(国际)，凭据不通用。

6. **加密只能在 repositories 层**（Contract 7 `crypto-only-in-allowed-callers`）→ 凭据经 `settings_repo` 透明 Fernet 解密后**以明文传入 adapter**；adapter 禁 `import core.crypto`。

7. **文件大小**：`bi_reports.py` ACK cap 500、实测 478（仅 22 行 headroom）→ share 端点**新建 `knot/api/bi_share.py`**（backend auto-cap 300）。前端 `check_file_sizes` **无 auto-discover** → 新 bi/ 文件**必须登记 `EXPLICIT_LIMITS`**（否则静默无守护）。

8. **RBAC 一致性缺口（kk 发现）**：`DashboardReport.jsx` 的「添加组件」+ 空态 gated 在 `isAdmin`（[:9/:16/:35](../../frontend/src/screens/bi/DashboardReport.jsx)），而工具栏编辑/重跑/删除用 `can('edit')` → 被授 edit 的非 admin 看得到「编辑」却看不到内联「添加组件」。**非安全洞**（后端 PUT/refresh 均 `require_report_perm("edit")` 兜底），是一致性缺口。修 = 传 `canEdit={can('edit')}` 进 DashboardReport（D2）。
