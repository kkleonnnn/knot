| 包 | 实装 | 正确上界 |
|---|---|---|

| `python-multipart` | **0.0.32** | ⚠️ `<0.0.33` —— 0.0.x 连 minor 都不稳定，`<0.1` 等于不设界 |

⇒ **下限也必须抬到实测系列**（现在 `fastapi>=0.111.0` 声称支持 26 个 minor 前的版本，从未测过）。
⭐ 而 Codex 补的那句我要放大：**别声称区间内所有点都验过 —— 真正验过的点是 lock 那一点。**
区间的作用只是「不让 pip 解析到明知会坏的地方」，不是「这些都能用」。

### F7' R4 —— 只改一行会直接文件不存在（实测）

`Dockerfile:12` = `COPY requirements.txt .`；`:13` = `RUN pip install -r requirements.txt`
⇒ 把 `:13` 改成读 lock 而不改 `:12`，**lock 根本没被 COPY 进来** ⇒ 构建当场失败。
⚠️ 而**纯负断言（「不得再 install requirements.txt」）连这个都测不出来** ——
删掉整个安装步骤它也通过。⇒ 必须**正向断言**「lock 被 COPY **且**被消费」。

### F8' R10 —— `requires-python` 与实际不符（实测）

`pyproject.toml:9` `requires-python = ">=3.9"`，而 CI **3 处**都是 `python-version: "3.11"`、
镜像是 `FROM python:3.11-slim` ⇒ **3.9/3.10 从未被任何东西验过**。⇒ 收敛到 `>=3.11`。

### ⭐ §2.1 我发现守护者两段之间有张力，给出解法（**本稿唯一的设计分歧，请裁**）

- **守护者 §II-R3** 采纳「lock 当 **constraints** + 安装后集合等值」（因为它顺带解 extras）；
- **守护者 §III** 却把阻断 lane 写成 `pip install --no-deps -r requirements.lock` + `pip check`。

⚠️ **两者的安装方式不同** ⇒ 若 CI lane 用 `--no-deps -r lock`，它**验的不是生产安装路径**
（生产是 constraints 形态、且带 extras）⇒ **lane 绿而生产可能坏**，正是 R8 要防的那类。

⇒ **我的解法**：**CI lane 必须用与 `Dockerfile` 逐字相同的安装命令**，然后**再叠加**三层证明：
1. `pip check` —— 证明依赖闭合（无缺失/冲突）；
2. **集合等值**：`pip freeze` 规范化后 == lock 规范化后（证明**没有** lock 外的包被拉进来）；
3. ⭐ **用该环境跑后端全量**（R8 —— 这条是全套里最关键的，见下）。

**为什么 3 不可省（Codex R8，守护者称「他最好的一条」）**：
代码若开始用「区间内新版才有的 API」⇒ 浮动 lane **绿**（它装的是新版）· lock 仍满足区间 ·
**只有生产炸**。⇒ 「lock 过期则 d5 会红」**不成立** —— d5 只比版本区间，看不见 API 用法。
**唯一能抓到它的是「用 lock 装出来的环境跑全量」。**

### §2.2 阻断 lane 的形态（守护者 §III，我采纳并加一句）

`actions/setup-python@3.11`（runner 本就是 linux/amd64，与镜像同解释器同 libc 族）
⇒ **零 Docker Hub 拉取** ⇒ 不把 `continue-on-error` 当初要避的 rate-limit 噪声请回来。
⚠️ 我加一句诚实边界：`setup-python` 的 3.11 与 `python:3.11-slim` **不是同一个二进制**
（不同构建、不同 libc 细节）⇒ 本 lane 证明的是「**lock 在 linux/3.11 上闭合且能过全量**」，
**不是**「与生产镜像逐字节同构」。后者只有 docker job 能证，而它非阻断 ⇒ 明说，不含糊。

## §5 诚实收窄 —— 本片**不**声称

1. ⭐ **不声称「镜像可复现」**（Codex R12，守护者称比依赖漂移更大的缺口）：
   `python:3.11-slim` / `node:20-slim` 这些**基础镜像 tag 会移动**，而本片不钉 digest。
   ⇒ 只可声称「**Python 运行时的版本集合可复现**」。**`docker save` 仍是唯一可靠回滚物。**
2. **不声称与生产镜像同构**：阻断 lane 用 `setup-python`，与 `python:3.11-slim` **不是同一个二进制**（§2.2）。
3. **不声称区间内所有点都验过** —— **验过的只有 lock 那一点**（R9）。
4. **不声称旧 tag 可复现** —— lock 只对引入它之后的 tag 有效。
5. **不钉 `requirements-dev.txt`** —— 沿用 ruff 先例的「本地浮动 = 早发现」那一半。
6. **不上 `pip-tools` / `uv`** —— 不引入新工具链；`pip freeze` 在容器内跑已够。
