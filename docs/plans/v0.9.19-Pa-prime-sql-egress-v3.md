## §0 ⛔ 先看这一条 —— 本片唯一刻意的 fail-open，请 Stage 3 优先裁决

> **升级后到运维跑完 grandfather CLI 之间，起源租户 `allowed_db_hosts` 为 `NULL` ⇒ 本片选择「放行 + 大声 WARN」。**

**为什么不是拒**：kk 已裁 **M6**（grandfather 由**人工跑 CLI**，不做自动 seed）
⇒ 升级瞬间列必然是 NULL ⇒ 若拒，**部署方自己的全部 SQL 数据源当场打死**，
而这正是前两版被推翻的那条（「升级即断网」）。

**为什么可以接受**（三条，缺一不可）：
1. **不比今天差** —— 今天该路径**零 allowlist**；
2. **可观测** —— 每次启动逐租户 WARN，且消息点名「跑哪条命令来结束这个状态」；
3. **有终点** —— 运维跑完 CLI 即消失。

⚠️ **执行者不替 kk 接受它。** 若 Stage 3 否决，替代是
「NULL 一律拒 + 把跑 CLI 写成升级硬前置」（语义最干净，代价是漏跑就全断）。

## §2 修法

### D1 —— 两道门（第二版已确立，保留）
| 能力 | 门 | 层 |
|---|---|---|
| 「**登记**一个指向 host X 的数据源」 | `POST`/`PUT` → **400** | 端点 |
| 「**连到** host X」 | `create_engine` 本体 | 适配器（纵深） |

⚠️ **第三个登记入口**：`users.doris_host`（`admin/users.py`）—— 按同一理由该有 400 门（Stage 2 E9）。
⚠️ **`asyncio.gather` 无 `return_exceptions`** ⇒ 门抛异常会让整个 `/status` **500**（Stage 2 E8）
⇒ `_test_source` 内必须自己接住并转成 `"error"`，**但要先 `reraise_if_tenant_error`**（C0 已立的范式）。

### D2 —— grandfather 改**显式 CLI**（kk 裁 M6）
```
python -m knot.scripts.set_db_allowlist --tenant <slug|id> --from-existing [--dry-run]
```
照 `reset_admin_password` 的形状：**`--tenant` 必填**（v0.9.15 立的「破坏性工具不得有默认目标」）。
- `--dry-run` 打印**将固化哪些 host、各自来自哪个来源**，⇒ ⭐ **固化前必须有人看一眼**
  （Stage 2 E3：升级前租户 admin 就能往 `db_host` 填任意值 ⇒ 自动 seed 会把
  `169.254.169.254` 之类**一起祝福**，且 `platform_audit` 是 append-only、**永久不可清除**）；
- 写入经 **`tenant_repo.update_tenant`**（v0.9.8 单一写口）⇒ 自动 stamp + **同事务** `platform_audit`。

**三个来源**（缺一即打死一类场景）：`data_sources`（**须 `WHERE db_type != 'http'`** 且**排除 `''`** —— Stage 2 E5）
· `users.doris_host` · `cfg.DEFAULT_DB_HOST`（⚠️ 默认值是 `"localhost"` ⇒ 未设 `DB_HOST` 的部署会把
`localhost` 塞进每个租户名单，Stage 2 E6 ⇒ **仅当它真被某个数据源用到时才纳入**）。

⚠️ **空结果写 `NULL`，不写 `''`** —— `''` 是三态里「部署方明确的禁」，与「还没配」不可区分。

### D3 —— ④ 脱敏判据改「读者是谁」（kk 已裁）
`platform_audit` **记内容**（读者 = 部署方自己）· 租户可达面**绝不出现**。
⚠️ **与 `test_allowlist_column_registration` 登记项⑤直接冲突**（它要求列 ∈ `_REDACTED_IN_AUDIT`）
⇒ 该项必须同片改写，**且改写后 §4-10 的注入不得同时打红它**（否则不再「唯一抓住」，Stage 2 E10）。

### D4 —— ⭐ 把「必须同构」从派生断言里拆出来（本版新解，替代「开例外」）
**第二版实测**：只加一列、其余不动 ⇒ **15 failed**，且**打红既有两列**
（`assert n_calls >= len(_MANAGED)` ⇒ 2>=3）。

**根因**：我把「**同一种解法**」和「**同一个性质**」混为一谈了 ——
断言写的是「**每份 allowlist 都必须有 env-fallback WARN**」，
而真正该守的是「**每份 allowlist 都必须有能让运维知道它当前处于什么状态的启动期观测口**」。

⇒ **改法（不是开例外，是把断言写准）**：
- 判据从「**数调用次数**」改为「**每个 resolver 模块都被启动序调用过至少一次**」（按模块匹配 ⇒ 加列不打红既有列）；
- ⚠️ **同时钉住观测口的最低内容** —— 必须能区分**三态**（已配 / 明确禁 / 未配），
  否则放宽后它退化成「有个函数被调用过」。**这一钉让工作量回来，但它比开例外诚实。**

### D5 —— 反向断言（Stage 2 E1 订正锚点）
锚点**不是** SQL 文本 + AST，而是 **`init_platform_db()` 跑完后的 `PRAGMA table_info(tenants)`**
（v0.9.12 那 3 处假红同形）。判据从「叫 `allowed_*` 的列」改为「**任何被 resolver 读取的列** ⊆ 元组」
（⚠️ 两侧同用 `startswith("allowed_")` 会让不叫这名字的列**两侧都不可见** ⇒ 恒真）。
⚠️ **诚实收窄**：运维手工 `ALTER` 出来的列，这条**结构上答不了**（而 `SELECT *` 会让它自动进 ctx）。
