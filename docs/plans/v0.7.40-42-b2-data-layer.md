## §3 PATCH v0.7.42 — B2.2 Doris statement timeout（仅 timeout · offload 推迟）

### §3.1 决议
Doris engine（`doris.py:22 create_engine`）当前 `connect_args={"ssl_disabled": True, "connect_timeout": 3}` **只有 TCP connect 超时，无 statement/read 超时**；唯一 runaway 守护 = `LIMIT 500`（`MAX_RESULT_ROWS`，只 bound 返回行数非墙钟时间）。加 PyMySQL `read_timeout`（socket 读截止）作可用性守护。

### §3.2 文件改动（精确）
**`knot/adapters/db/doris.py:27`**：
```python
connect_args={"ssl_disabled": True, "connect_timeout": 3, "read_timeout": DORIS_READ_TIMEOUT},
```
`DORIS_READ_TIMEOUT` 从 `config/settings.py` 读，`KNOT_DORIS_READ_TIMEOUT` env 覆盖（守护者 R5.2 LOCKED），**默认 60s**（守护者背书 + kk 确认）。config 注释镜像 §3.3 诚实边界（socket 读超时下限，非墙钟）。

### §3.3 红线 + ⚠️ 诚实边界（防 CHANGELOG 过度宣称）
- ⚠️ **`read_timeout` 是 per-socket-read 截止，非累计查询墙钟上限**（verifier 校正）：稳定流式返回行的长查询（每包 < timeout）**仍可总时长超 read_timeout**。真墙钟上限需 Doris 服务端 session var `query_timeout`，但 `_is_safe_sql`（`doris.py:338`）拦 `exp.Set` 节点 → 不能经 `execute_query` 下发 → 须 out-of-band raw connection（本 PATCH 不做）。→ **CHANGELOG 措辞 = "socket 读超时守护（catches 完全 stall 的连接，非 long-but-progressing 扫描）"，不写"statement timeout 根治"。**
- **影响所有 `create_engine` 出的 engine**（含 schema introspection / `information_schema` 加载）→ `DORIS_READ_TIMEOUT` 须**足够宽**不误杀合法慢 schema 加载（60s 建议值理由）。
- 成功路径 byte-equal（正常查询远快于 60s，无感）；`execute_query` 返回契约 `(rows, error)` 不变。
- **offload 不做**（§0.1 DEFER）——本 PATCH 仅 connect_args 一行 + config 常量。

### §3.4 开放项 — ✅ CLOSED
