## §1 两个缺陷的具体形状

### D1 · webhook 出网未租户域化（跨租户数据出境 + 可用性双坏）
`webhook.py:26` 读进程 env；生产调用点 `api/admin/monitors.py`（monitor 行在**租户库**）。
- **出境**：租户 B 的 admin 建 monitor，`action_target` 指向**部署方 env 白名单里的内网 host**
  ⇒ 命中即 POST（body 含指标名与值）⇒ 数据推进部署方内网 / 反向探测其端点。
- **可用性**：租户 B **无法**配自己的 host ⇒ 它的 webhook 全废。
- ⇒ 与 v0.9.7 修掉的 `url_allowlist` **完全同形**，且**从未进过 R-T-GATE 清单**。

### D2 · lark token 缓存：**命中缓存这条路上，secret 根本不参与**（kk 2026-08-07 上修一档）
`_tenant_token()` 实读顺序（`lark.py:54-58`）：`key=(region, app_id)` → `_token_cache.get(key)`
→ 未过期**直接 `return cached[0]`** → **只有 miss 时才带 `app_secret` 去 POST**。
⇒ 参数 `app_secret` 在命中路径上**一次都没被读**（已逐行复核）。

⚠️ **所以定性不是「跨租户身份借用」，而是更硬的一句**：
> **命中缓存时，调用方没有证明过任何东西。**

租户 B 把 `app_id` 填成 A 的（**`app_id` 是标识符、不是秘密**）、secret 随便填 ⇒ 命中 ⇒
拿到 **A 的 `tenant_access_token`** 并以 A 的身份发消息（约 2h）。
⇒ **修法不只是「隔离」，是把 secret 的承重地位还回去。**
⚠️ 该缺陷 v0.9.5 测绘期已验到并记进记忆，**但从未登记进 R-T-GATE 清单**。

## §2 修法（照 v0.9.7 ②③ 已走通的形状）

### D1
- 平台库 `tenants` **加一列** `allowed_webhook_hosts`（本仓第二条平台迁移；第一条是 v0.9.7 的 `allowed_http_hosts`）。
- **三态语义，判据必须 `is None`**（与 v0.9.7 逐字同构）：
  `NULL`=未配置（**仅起源租户**回退 env + 启动 WARN）/ `''`=部署方明确的「禁」（不回退）/ 非空=该集合。
- **永不与 env 或其他租户取交集/并集**（取交集是反向的：为给客租户开权会同时放宽起源租户）。
- 载体选「`tenants` 的一列」而非独立表：`get_tenant`/`list_active_tenants` 都是 `SELECT *`
  ⇒ 加列自动进 tenant ctx ⇒ adapters 只读 `core.tenant_context`，**零分层例外**
  （`adapters-no-business` 禁 adapters → repositories）。
- ⚠️ **拒绝消息不得回显 allowlist**（v0.9.7 的 #262 同类缺陷：整份内网主机清单经 SSE 泄给租户 admin）
  ⇒ 诊断进日志且**连条目数都不记**。

### D2
- `_token_cache` 键改为 **`tenant_cache_key(region, app_id)`** ——
  与其余 7 处缓存**同一个 helper**，不自创第二套键法。
- ⭐ **键再含 `sha256(secret)` 前 16 位**（不存明文、不进日志）。
  ⚠️ **这一条要写两个独立理由，不能只写一个**（kk 指出：否则将来有人为省一次 hash 把 secret
  摘出键，那时理由②看起来还成立、而理由①已经塌了）：
  - **理由①（安全 · 承重）**：**secret 必须参与判定**。没有它，命中路径上调用方零证明。
  - **理由②（正确性）**：同租户内**换了 secret 要立刻生效**，而不是等旧 token 自然过期（≤2h）。
  ⇒ 二者独立成立；删掉 secret 摘要会**同时**破坏①，即使②看上去还能用别的方式实现。

## §4 验收
1. AST 数清 webhook 发送函数的**全部**调用点 + `_token_cache` 的**全部**读写点（入口不止一个）。
2. D1：非起源租户配了自己的 allowlist ⇒ 请求**真的发出**（正对照，防「拦住所有人」式假通过）。

4. D2：先证明缓存**真被命中**（同租户第二次不发 token 请求），再证跨租户**不**命中。
5. ⭐ **D2 核心一条（kk 指定 · 不可用「不同租户拿到不同 token」替代）**：

   ⚠️ 「不同租户拿到不同 token」只证明了**隔离**，证明不了**secret 承重** —— 两者是不同的性质。
6. D2：同租户换 secret ⇒ 立刻不命中旧 token（理由②）。
