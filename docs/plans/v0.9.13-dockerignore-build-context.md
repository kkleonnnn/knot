## §2 设计 —— 两个 commit

### e1 `.dockerignore`（**必须是本片第一个 commit**）

**默认拒、显式放行**（allowlist 形态更安全，但 Docker 的 `.dockerignore` 语义是 denylist +
`!` 反排除 ⇒ 用 `**` 全拒 + `!` 放行**会**破 `COPY . .` 的可维护性）
⇒ **本片用 denylist，但把「必须被排除的」写成一份有理由的清单**，并由 e2 的**双向**断言守。

必排（每条给理由）：
| 条目 | 理由 |
|---|---|
| `.env` / `.env.*`（保留 `!.env.example`） | 含 `KNOT_MASTER_KEY` / `JWT_SECRET` / DB / LLM key |
| `.git` | 125M + **全部历史**（含任何曾被 amend 掉但仍在 pack 里的东西） |
| `knot/data/` | 租户库 + **36 个 `.bak*`**（含明文凭据）。运行时是 volume 挂载 ⇒ 镜像里不需要 |
| `.venv/` | 205M，且是**宿主 3.12** 的产物（镜像是 3.11）⇒ 进去只会冲突 |
| `**/node_modules/` | 229M；builder stage 自己 `npm ci` |
| `__pycache__/` `*.pyc` | 宿主字节码 |
| `.claude/` | worktrees + 会话产物 |
| `*.bak*` | 兜底（即使将来 `.bak` 出现在别的目录） |
| `.pytest_cache/` `htmlcov/` `.ruff_cache/` | 构建无关 |

⚠️ **必须保留的（否则镜像坏）**：`knot/`（除 `data/`）· `requirements.txt` ·
`frontend/`（除 `node_modules`）· `pyproject.toml`。

### e2 双向断言 —— **阻断且不需要 docker**

⭐ **判据作用在「计算出来的构建上下文」上，不是在镜像上** ——
因为 `docker build smoke` 是 `continue-on-error: true`（F4-2）⇒ 在它上面挂断言 = 挂在非阻断 job 上。
⇒ 纯 Python 复现 `.dockerignore` 的过滤，得到**将被送进 build 的文件集**，再双向断言。

- **Se1（负向）**：上下文里**不得**出现 `.env` / `.git/` / `*.bak*` / `.venv/` / `node_modules/` / `__pycache__`
- **Se2（正向 —— 不可省）**：上下文里**必须**含 `knot/main.py` / `requirements.txt` /
  `frontend/src/version.js` / `frontend/package.json` / `pyproject.toml`
  ⭐ 理由 = Codex R4 的教训：**纯负断言在空集上恒真** ——
  一个把整个仓库都排除掉的 `.dockerignore` 会让 Se1 通过而镜像完全坏掉。
- **Se3**：`.dockerignore` 里每条必排项都**在**（防有人删掉一行）

## §3 v3.1-B 承重面枚举表（凭据 / 部署）

1. **fail-open 面**：`.dockerignore` 漏一条 ⇒ 秘密进镜像（fail-open）⇒ Se1 守。
   ⚠️ 反向也危险：排太多 ⇒ 镜像坏 ⇒ **Se2 正向断言**守（这一半绝不能省）。
2. **oracle 能力 + 注入真能产生它吗**：判据能表示「某文件进了构建上下文」吗？——
   能，且**必须自己实现 `.dockerignore` 语义**（含 `!` 反排除、`**`、目录前缀）。
   ⚠️ 注入验证：删掉 `.dockerignore` 里的 `.env` 那行 ⇒ Se1 必须红（**实跑**）。
3. **「那一行」族**：门在 **`.dockerignore` 本身**（`docker build` 读它的那一刻）；
   断言在**构建上下文**这一层，而不是在非阻断的 docker job 上（F4-2）。
5. **散文规则**：「必排清单」是新散文 ⇒ 由 Se3 守（少一行即红）。
6. **声明 vs 生产者**：`.dockerignore` 的消费者是 `docker build`（真消费者）；
   ⚠️ **不再声称** docker job 是「白拿的守护」（F4-2 已证伪）。
7. **顶班**：摘掉 Se1 后必须无人再拦 —— 实跑确认没有别的测顶班。
8. **既有测的绿是真的吗（扫两侧）**：`tests/scripts/test_dockerfile_copy.py` 断言 3 条 `COPY` 行
   —— ⚠️ **本片不改 Dockerfile** ⇒ 它们的理由不受影响。**但须复核**：`COPY . .` 之后若某文件
   本来靠它进镜像、现在被 ignore 掉，那条 `COPY` 的语义会变 ⇒ **Se2 的正向清单就是这条的答案**。
9. **契约冲突**：无（不动 Python import 层）。
10. **策略题的影子**：出现了 —— 「denylist 还是 allowlist」。
    ⇒ 不是自造的（Docker 的语义决定了 denylist 更可维护）；用**双向断言**补上 denylist 的固有弱点。
11. **诚实收窄 —— 本片不声称**：
    - **不**声称镜像「可复现」（基础镜像 tag 会移动 —— Codex R12；`docker save` 仍是唯一可靠回滚物）；
    - **不**动 `Dockerfile`（`COPY . .` 保留；改成显式 COPY 列表是更大的重构，留 backlog）；
    - **不**处置 `knot:deploy-test`（非本会话产物，留 kk 定）；
    - **不**声称历史镜像都干净 —— 只声称**本机今天那两个已销毁**，且从未离开本机。
