## §3 本片设计（两个 commit，零部署契约改动）

### e1 `.dockerignore` —— 只排无争议的

| 条目 | 理由 |
|---|---|
| `.env` · `.env.*` | 含 master key / JWT / DB / LLM key。⚠️ **R8：不反排 `.env.example`** —— `!` 是唯一顺序相关的规则，为一个模板文件引入顺序依赖不值 |
| `.git` | 125M 全部历史；worktree 下是指针文件（泄漏宿主路径/用户名）。**不写斜杠**（理由见 §0-R7） |
| `data/` · `knot/data/` | **两个都排**（R1）：前者是 DEPLOY 挂载点、部署主机上会存在；后者是本地 dev 的库 |
| `.venv/` | 205M，且是宿主 **3.12** 产物而镜像是 **3.11** |
| `**/node_modules/` | 229M；builder stage 自己 `npm ci` |
| `**/__pycache__/` · `*.pyc` | 宿主字节码 |
| `**/*.bak` · `**/*.bak-*` | 兜底：`.bak` 会出现在 `tenants/<id>/`，且 `-wal`/`-shm` 旁文件**不被 `*.bak` 匹配**（v0.9.12 实测） |
| `.pytest_cache/` · `.ruff_cache/` · `htmlcov/` · `.claude/` | 构建无关 |
| `tests/eval/cases.yaml` · `tests/eval/fake_schema.txt` | 测试专用，**无两难**（Codex，守护者确认 ✅） |

**⚠️ 必须保留**（Se2 正向清单，按 R6 修正）：`knot/`（除 `data/`）· `requirements.txt` ·
`frontend/src/` · `frontend/package.json` · **`frontend/package-lock.json`**（`npm ci` 强制要它） ·
`frontend/vite.config.js` · `knot/repositories/schema.sql` · `knot/repositories/platform_schema.sql` ·
`knot/prompts/` · `knot/services/agents/_template_catalog.py`
⚠️ **不含 `pyproject.toml`**（R6：Dockerfile 0 命中，列进去是假信念）。

### e2 哨兵 —— **真 Docker 是门；Python matcher 只是预筛**

⭐ **我升级立场，与守护者一致**：上一稿把 Python matcher 当安全 oracle 是错的 ——
**被测对象就是 Docker 的行为，不用 Docker 就测不了它**。

| # | 层 | 断言 | 阻断？ |
|---|---|---|---|
| **Se0** | Python | `.dockerignore` 每条必排项在（格式守卫，R8 降级后的定位） | 是（快） |
| **Se1** | **真 Docker** | 在**合成 fixture** 上 `docker build` ⇒ 镜像内**不得**有 `.env`/`.git`/`*.bak*`/`.venv`/`node_modules`/`data` | 见下 |
| **Se2** | **真 Docker** | 同上下文 ⇒ 镜像内**必须**有上面那份正向清单 —— ⭐ **不可省**（R4：纯负断言在空集上恒真；一个把整仓都排掉的 `.dockerignore` 会让 Se1 通过而镜像完全坏掉） | 见下 |

**⚠️⚠️ R3+R4 的两条硬约束**：
1. **canary fixture 必须逐族真造** —— clean CI 上本来就没有 `.env`/真库/备份 ⇒ Se1 会**因为文件本来不存在而绿**
   = 对空集做否定断言恒真（**这正是我 v0.9.12 刚立的那条规则**）。
   ⇒ 逐族造：根 `data/` · 包内 `knot/data/`（含 `.db` + `-wal` + `-shm`）· `.env` + `.env.local` ·
   `.git` **文件**与 `.git/` **目录**两种形态 · `*.bak` + `*.bak-wal` · `.venv/` · **嵌套** `node_modules/` · 私有 catalog。
2. **⛔ mutant 只准跑在合成 fixture 上，严禁在真实含密钥工作树上跑「坏规则」的 Docker mutant**
   —— 否则一次 mutant 就**再造一个被污染的镜像**，而**我今天已经造过两个**（守护者放大 Codex 的提示，我完全接受）。

**阻断性怎么定**（R7 的 `continue-on-error` 有正当理由 —— 避免 Docker Hub rate limit 误杀 PR）：
本片的 Se1/Se2 **需要 docker build** ⇒ 无法照搬守护者给下一片的「不用 docker 的阻断 lane」。
⇒ **本片提案**：Se1/Se2 放进**现有的非阻断 docker job**，**但**用**合成 fixture 的最小 Dockerfile**
（`FROM busybox` + `COPY . /c`，**不拉 python/node 基础镜像**）⇒ rate-limit 面显著小于现有 job。
⚠️ **这是本片唯一的开放设计点，列入 §7 待守护者裁**：要不要为它单开一个阻断 job。

## §5 诚实收窄 —— 本片**不**声称

1. ⭐ **不声称「镜像最小化」**（守护者 §III-1）：`.dockerignore` 管的是**送进 daemon 的上下文**，
   **不管最终镜像内容** —— `COPY . .` 仍会把上下文里剩下的一切放进镜像。
   ⇒ 本片只可声称「**秘密不再进入构建上下文**」。改显式 `COPY` 列表 = 下一片（R5，且依赖 R2 的挂载决策）。
2. ⭐ **不声称私有 catalog 已处理** —— `_local_catalog.py` / `few_shots.yaml` **仍进镜像**（§1）。
3. **不声称镜像可复现**（Codex R12：基础镜像 tag 会移动，`python:3.11-slim` / `node:20-slim`）
   ⇒ `docker save` 仍是唯一可靠回滚物。
4. **不声称历史镜像都干净** —— 只声称本机今天那两个已销毁，且**未发现** push/save 证据（R9 措辞）。
5. **不处置** `knot:deploy-test`（非本会话产物，待 kk 点头）。
