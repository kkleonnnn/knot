## §0 口径（kk 2026-08-07 两次裁定，第二次修正了第一次）

**第一次**：「SQL 数据源出网 —— host 由部署方控，不接受租户自填」。
**第二次（本片依据）**：kk 补充事实 —— **「目前合作方的数据库和数仓都是我们团队部署的」**。

⇒ 该事实**改变了选项**（三选一的推理，逐条记下来因为它决定本片形状）：

| 选项 | 为什么不是它 / 为什么是它 |
|---|---|
| **不接受租户填**（第一次裁定的字面） | 要新建一条**部署方写入数据源**的路径（今天只有租户 admin 端点）⇒ 工作量远大于收益；且租户仍需自填库名/账号/口令，只有 host 被夺走 —— 收益不成比例 |
| **拒私网地址段**（业界标准 SSRF 解） | ⛔ **不适用** —— 部署方的库**本来就在内网**，拒私网段会把**正常用法全挡掉** |
| ⭐ **per-tenant allowlist** | ✅ 部署方知道全部 host ⇒ 名单**可维护**（不会退化成「每次找运维加一条」）；且**保住租户自助**（仍自己填库名/账号/口令） |

⚠️ **为什么必须 per-tenant 而不是一份部署方全局名单**（这是本片的核心安全论证）：
> 你们部署所有的库 ⇒ **所有租户的库 host 都在那份全局名单里**
> ⇒ 租户 B 可以把数据源指向**租户 A 的库 host**，然后猜凭据 / 读报错 = **跨租户探测**。

⇒ 第三份 allowlist：**`tenants.allowed_db_hosts`**，与已有两份同形。

| 面 | 列 | 状态 |
|---|---|---|
| HTTP 数据源读取 | `allowed_http_hosts` | ✅ v0.9.7 |
| webhook 外发 | `allowed_webhook_hosts` | ✅ v0.9.18 |
| **SQL 数据源连接** | **`allowed_db_hosts`** | ▶ 本片 |

## §1 缺陷（grounded）

`api/admin/datasources.py` 的 SSRF 守卫**函数体第一行**是
`if db_type != "http" or not http_config: return`
⇒ **SQL 数据源那条出网路径零 allowlist**。租户 admin（`require_tenant_admin`）可经
`POST /api/admin/datasources` 填**任意** `db_host` / `db_port`，或经
`POST /api/db/test` 直接建连接并**读回错误消息** ⇒ 内网端口扫描 + banner grabbing。

⭐ **它为什么在 Stage 2 三个 lens 里只有一个找到**（本弧最贵的一条方法论）：
> **按「找名单」的扫描面结构上找不到它 —— 因为它不是「另一份名单」，是「没有名单的那条路」。**
⇒ 已折进 CLAUDE.md：清扫「所有同类的 X」时，**先列出「所有需要被 X 管住的行为」，再看哪些没被管**。
三种伪装：被声明为无关的 · 形态不同的 · **压根不在的**（← 本条）。

## §2 修法

### D1 —— 门装在**能力被行使的那一行**（choke point）

**要管的行为 = 「用一个 host 建 SQL 连接」。** 全仓**恰 1 个** host 型入口：
`adapters/db/doris.py::create_engine(host, port, user, password, database)`
（`create_sqlite_engine` **无 host**，本地文件，不适用）。

**AST 实测调用点 6 处**，分两类：
| 类 | 调用点 | host 来自 |
|---|---|---|
| **现填** | `api/database.py:38`（`/api/db/test`）· `api/admin/datasources.py:81`（存前探测） | **请求体** |
| **已存** | `services/engine_cache.py:198/272/309` · `api/admin/datasources.py:263` | 租户库数据源行 |

⇒ **门放进 `create_engine` 本体**（而不是 6 个调用点各放一个）：
- **6 处全覆盖**，且**将来新增调用点自动受保护**（v0.9.6 `executor.execute` 已走通这个形状）；
- ⚠️ **「已存」那类也必须过门** —— 否则「先存进去、再让它被调用」就是绕过；
- ⚠️ **入口不止一个的检查**：`/api/db/test` 与数据源 CRUD 是**两个**入口，门在下游汇合点 ⇒ 两个都被管。

**已验前提**：`knot/main.py` / `repositories/` / `scripts/` 里 **0 处**调 `create_engine`
⇒ **没有无租户 ctx 的路径会撞门** ⇒ 装门不会打死启动序（与 v0.9.7 同）。

### D2 —— 三态语义与前两份**逐字同构**（不自创第三套）
```
raw = current_tenant().get(COLUMN_NAME)   # ⚠️ .get() 不得下标（v0.9.7 M2）
if raw is None:                           # ⚠️ 判据必须 is None（M1）
    if not is_owner_tenant(): return set(), "unconfigured"
    return _parse(os.environ.get(ENV_NAME, "")), "env-fallback"
return _parse(raw), "column"
```
⭐ **本片几乎白送** —— P-a 建的三样东西**正是为第三份准备的**：
- `test_allowlist_column_registration.py` ⇒ 新列**自动**被要求登记五处；
- `test_egress_allowlists_shared_properties.py` ⇒ 新列**自动**进三态性质表 + 启动 WARN 断言；
- `_REDACTED_IN_AUDIT` 哨兵 ⇒ **逼着**它进审计脱敏集合。
⇒ 加列的真实工作量在 `create_engine` 那道门 + `datasources.py` 那个 early-return。

### D3 —— 4 个出网点禁重定向（本片第二件事）
全仓**只有** `api/admin/datasources.py:71` 写了 `allow_redirects=False`。
未禁的：`webhook.py` · `lark.py` · `telegram.py` · `executor.py`（get + post）。
⇒ **allowlist 只管第一跳**：租户让自己**合规的** host 返 **307/308**（**保留方法与 body**）
即可把请求连同内容引向别处 ⇒ **域化当天就是装饰品**。
⚠️ **`lark.py:42` 是 `requests.post(url, timeout=…, **kw)`** —— `**kw` 会展开调用方参数
⇒ 加 `allow_redirects=False` 必须**防它被 kw 覆盖**（写在 `**kw` 之后，或显式 pop）。
⚠️ 既有测**零依赖**「跟随重定向」⇒ 禁它不打断任何测；**也因此没有测会因它变绿**
⇒ **必须新写判据**（见 §4）。

## §3 v3.1-B 承重面枚举（命中：egress · 租户隔离 · 凭据）

   ⚠️ 重定向那件事**同族**：门在「发请求的那一行」，不是决策点。
4. （并入 #3）

   全仓 `requests.{get,post,head,request}` 调用**必须**显式 `allow_redirects=False`

9. **契约冲突**：`adapters` 不得 import `repositories` ⇒ 走 `core.tenant_context`（两次已证可行）。

11. **诚实收窄**：本片**不声称** ——
    ⚠️ **凭据强度**：名单挡住「指向别家的库」，但**同一台 host 上不同 database** 仍靠数据库自身账号隔离

## §4 验收 —— 每条先答五问②

| # | 判据 | 注入 | 前 → 后 |
|---|---|---|---|
| 1 | 非起源租户配了 `allowed_db_hosts` ⇒ `create_engine` **真的建连**（正对照，防「拦住所有人」） | 门改回不校验 | 前：建连 → 后：仍建连 ⇒ **本条对 D1 无判别力**，它守的是**没把功能拦死** ⚠️ 故必须与 #2 成对 |
| 2 | 非起源租户 host **不在**名单 ⇒ `create_engine` **抛且零连接尝试** | 删掉门 | 前：抛 → 后：**真的去连**（用出网探针记录，不能只断异常 —— P-a0 清掉的正是「抛了就算」） |
| 3 | ⭐ **跨租户探测被挡**：租户 B 指向**租户 A 的 host** ⇒ 拒 | 名单改成部署方全局一份 | 前：拒 → 后：**放行** ⇒ 抓住「全局名单」这个错误设计本身 |
| 4 | `/api/db/test` 与数据源 CRUD **两个入口都被管** | 门只放在 CRUD 那侧 | 前：两个都拒 → 后：`/api/db/test` **放行** ⇒ 抓住「入口不止一个」 |
| 5 | 三态 × 起源/非起源逐格（**自动**由 P-a 的共享性质表覆盖） | 判据改 `if raw:` | 前：`''`→`column` → 后：`''`→`env-fallback` |
| 6 | 启动 WARN 存在**且接线**（**自动**由 P-a 的派生断言覆盖） | 删函数 / 删接线 | 各自红，消息不同 |
| 7 | **禁重定向**：mock 返 308 + `Location` 指向另一 host ⇒ **请求没跟过去** | 去掉 `allow_redirects=False` | 前：只有 1 次请求到原 host → 后：**第二次请求到新 host** ⇒ 用出网探针的 URL 列表当 oracle |
| 8 | `lark.py` 的 `**kw` **覆盖不了**禁令 | 调用方传 `allow_redirects=True` | 前：仍不跟随 → 后：跟随 ⇒ 抓住那个覆盖坑 |
| 9 | AST 哨兵：新增一个不带 `allow_redirects=False` 的 `requests.post` ⇒ 红 | 加一处裸调用 | 前：绿 → 后：红 |
