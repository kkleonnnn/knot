## § 3 文件改动（per-fix，grounded file:line）

### F1 — 上传问数隔离（HIGH · 最优先）
**现状**：`engine_cache.py:16-17` `_KNOT_DB=.../data/knot.db`；`_upload_engine=create_sqlite_engine(_KNOT_DB)` → 上传引擎 = 应用主库。`query.py:54` 上传分支返 `_upload_engine`。`_is_safe_sql`（doris.py:326）只挡写不挡跨表读。
**修法（Stage 2/3 定选项，推荐 A）**：
- **选项 A（推荐 · 物理隔离 fail-closed）**：上传数据表 `t_*` 迁到**独立文件** `knot/data/uploads.db`（部分逆 v0.2.4 合并——仅数据表，`file_uploads` 元数据行仍留 knot.db）。`_upload_engine` 指向 uploads.db；`uploads.py` 的 `load_rows_to_sqlite` 写入 uploads.db。上传问数引擎物理不含主库表。须：一次性迁移已存 `t_*`（knot.db → uploads.db，幂等 + .bak）。
- **选项 B（次选 · AST 表域校验）**：保留单文件，上传问数生成 SQL 后用 sqlglot 提取引用表，**拒绝**引用非 `rec["table_name"]` 的表（复用 fragment_guard 思路）。较轻但依赖 AST 提取完备性（弱于物理隔离）。
- **选项 C（attach-read-only）**：SQLite ATTACH 不限文件内表可见性 → 不成立，排除。
**改动文件**：`engine_cache.py`（_upload_engine 目标）+ `uploads.py`（写入目标 + F5）+ 迁移脚本（选 A）+ 测试。

### F2 — use_agent 成功公式源头修
**现状**：`sql_planner.py:196`（sync）+ `:350`（async）：
`success = bool(final_sql and not final_error) or bool(final_sql and final_rows is not None)`
第二子句恒真（`final_rows` 初值 `[]`、`execute_query` 出错返 `([],err)` 永不返 None）→ `success=bool(final_sql)`，DB 执行错（进 observation 不进 final_error）耗尽 max_steps 仍 True。
**修**：删第二子句 → `success = bool(final_sql and not final_error)`（sync + async 两处一致）。**流式主链路已有 v0.7.20 caller 补丁**（`query_steps.should_run_presenter` = success AND not error），本修消除源头恒真，不改流式行为（byte-equal 结果）。

### F3 — SQLite busy_timeout
**现状**：`base.py:16` `get_conn()` 只设 `PRAGMA journal_mode=WAL`，默认 busy_timeout=0 → 第二 writer 立即 SQLITE_BUSY。
**修**：`get_conn()` 加 `conn.execute("PRAGMA busy_timeout=5000")`（或 `sqlite3.connect(timeout=5)`）。让并发写等待非立即失败（缓解调度器 tick + 用户写并发的 `database is locked`）。

### F4 — 2 SSRF
- **①** `database.py:33` `POST /api/db/test` 依赖 `get_current_user` → **`require_admin`**（对齐 datasources CRUD 的 admin-only）；`test_connection` 返回收敛为不区分 refused/auth-fail 的统一文案（去 error_msg 原文透传）。
- **②** `admin/datasources.py:42` `_test_source` 的 HTTP HEAD + `admin_create/update_datasource` 存 http_config 前，**调 `check_url_allowed`**（复用 `url_allowlist`，与 executor.py:97 单一守卫对齐）。

### F5 — 上传表名 user 前缀
**现状**：`uploads.py:65` `table_name = "t_" + re.sub(...)[:32]`（无 user 归属）。
**修**：`table_name = f"t_{user_id}_" + sanitized[:24]`（或按 upload_id）。与 F1 正交（F1 隔离跨库、F5 防同库内跨用户覆盖）。注意长度上限 + 与 `file_uploads.table_name` 存储一致。
