## §2 三条 BLOCKING（Stage 3 §I，全部必修）

### B-1 PEP 562 代理管不到 catalog.py **自身函数体内 10 处裸名读**
模块内 `TABLES` 编译成 `LOAD_GLOBAL`，只查模块 `__dict__` + builtins，**永不触发 `__getattr__`**。
命中点：`current_catalog:54-58` · `get_table_full_names:173` · `is_http_table:200` · `get_http_spec:218` ·
`get_field_mapping:233` · `get_http_tables:244` · `reload:88` 的 `global` 声明。
**危险支是静默的**（§0.5 实测坐实）：`reload()` 的 `global`+赋值一跑就把 6 名复活 → 代理静默死亡、租户槽闲置、
**串供照旧且生产无断言 = 无声**。
**且不能简单改走 `current_catalog()`**：5 个 HTTP helper 读的是 reload 写入、**file-merge 过的** TABLES，
而 ctx 载体里没有 HTTP 表 → query 内 ctx 已 set → HTTP 表消失 → 同样静默落 SQL。
**修法（§V-3）**：① `reload()` 全程**局部变量**构造 state → 最后**原子发布**到槽（**不用 `global`**）；
② catalog.py 内部 10 处读**全部改显式载体访问器**；③ 加**运行期断言**（reload 之后 6 名仍不在 `__dict__`）；
④ 哨兵升级（§4 A-3）。本稿 §3 表逐条声明「哪个 helper 读哪个载体」。

### B-2 `_load_from_db` 硬编 `get_catalog(1)` 与 catalog_id 维**直接冲突** → 删该维
`reload` 的 DB 源恒为 `catalog#1`（`catalog_loaders.py:68`，legacy 兜底同为 `app_settings` 4 键、无 catalog id），
而 `pick_http_route` **每 query 无条件 reload**（`http_planner.py:130`，调用点在 SSE generator 内 `query.py:290-292`），
此时 ContextVar 已被 `capture_active_catalog` 设成该用户 active catalog **N**（`query.py:234`）。
→ 若让 reload 写「当前 catalog_id」槽：**active catalog=7 的用户发一次 query，就把 `catalog#1` 的
tables/lexicon/business_rules 写进 `(tid,7)` 槽** → 该租户此后 `schema_filter` 选表 / `sql_planner` business_rules
全拿 `catalog#1` 口径 = **租户内跨 catalog 口径污染，每 query 重复发生且绿测**。
→ **载体 = tid 单键、单默认槽**；「reload 输出只落租户默认槽、per-request ContextVar 是另一载体」这个
**非对称是承重的，不是可清理的重复** → 写成红线 R-2。

### B-3 file 层 + HTTP env 凭据是**租户盲**的，per-slot 原理上修不了 → **独立 R-T-GATE blocker**
`_load_from_files` 导入**单一进程级** `_local_catalog.py`（本部署真实存在 10117 bytes、gitignore = 真业务目录），
且 merge 规则让它对**空 DB 租户直接生效**（`catalog.py:147` rules fallback · `:109` · `:116-122` file HTTP 表无条件权威追加）。
- **失败一**：开通租户#2、`catalogs` 行空 → 其 clarifier/presenter/sql_planner prompt 被注入**部署方真实业务规则 + 真实库表清单**。
- **失败二（更重）**：租户#2 lexicon 命中任一 file HTTP 表 → `get_http_spec` 返 file spec → executor 用**进程 env** 取凭据
  （`adapters/http/executor.py:87-88`），host 白名单同为进程 env（`url_allowlist.py:30`）→ **租户#2 用租户#1 的凭据读其实时接口 = 跨租户数据出境**。
→ OUT-6/D7 从「写进 DEPLOY 免责」**升格为硬前置**：**per-tenant file catalog / per-tenant http_spec 凭据 / egress 租户域化**
三项写入 R-T-GATE 就绪清单（§5）。**本片不做，但必须登记 —— 否则「隔离栈就绪」是假的。**

## §4 红线

- **R-1 OOS-1v2**：租户库内不得新增 tenant_id/project_id 列。

- **R-4 fail-closed 不倒退**：`current_tenant()` 的 raise 不得被新增 `except` 吞（D8' 是加强）。
- **R-5 R-SL-40 口径烘焙**：血缘/monitor 仍走**显式实参**路径（`get_catalog(orig["catalog_id"])`），本片不改。
- **R-6 R-T-GATE 不动**；且**本片完成 ≠ 隔离栈就绪**（B-3）。
- **R-7 死码不接线**：`augment_schema_with_http_tables`（含 `:558` reload 写点）**原样留**（F-2 裁定）。
- **R-8' eval 先补 ctx 再看数字，且须 handle「无 tenant ctx 的 CLI」这一类别**（§III-5）：
  D6' 删 import 期 reload 会**静默清零 CLI eval harness 的 business_rules** → 复刻 2026-07-18 假回归机制。
- **R-9 A-3 哨兵三件套**（B-1 推论）：禁 from-import 值绑（补 `FIELD_LABELS`）+ **禁 `global <6名>` 语句** +

## §6 验收（每条须 revert-to-bad 自证；**逐条**对齐真跑过的 revert，不用「全部」笼罩）

1. **跨租户串供关闭**：复刻测绘双租户脚本形态（现成坏基线）。revert（槽回退进程全局）→ 红。
2. **⭐ 代理未被静默旁路**：断言 reload **之后** 6 名仍**不在** `catalog.__dict__`。
   revert（reload 改回 `global`+赋值）→ 红。**（§0.5 实测：这是唯一能抓住「静默复活」的断言）**
3. **测序无关**（§III-4）：验收测**不得**依赖文件序 —— poisoner 在 `#122/#127`，而本片惯例把隔离测放 `tests/` 根 = `#137+`
   在其后 ⇒ 首跑即红。修法三件：(a) **3 处** `setattr` 站点改注入载体；(b) 换**顺序无关的静态 AST 哨兵**
   （禁 `setattr`/`monkeypatch.setattr` 的 attr 名落在那 6 名上）；(c) 加 reload 后运行期断言。
4. **HTTP 链不静默失效**：租户 B ctx 下 `is_http_table`/`get_http_spec`/`get_http_tables` 不命中 A 的表；
   **且单租户下 file HTTP 表仍在**（防 §0.1 的 v0.7.29b 复发）。revert（槽改用 `_parse_catalog_content`）→ 红。
